# 홈 IA — 정보구조와 화면 흐름

작성자: UX/IA 디자이너 · 전제: `design/LIBRARY-BRIEF.md` §5, `design/UX-SPEC.md` 3.1
범위: 구조·순서·비중·전환만 정의한다. 시각 스타일(책등 타이포·모션)은 각 비주얼/모션 담당 문서(`design/mock/type.html`, `design/mock/motion.html`)를 따른다.

실측 기준: 2026-09-10, `content/graph.json` / `content/fields.js` 직접 파싱.

## 0. 실측 — 브리프의 전제가 이미 낡았다

`UX-SPEC.md`는 "150편 중 116편(77%) 작성, seed 34편"을 전제로 3.1의 홈 와이어프레임과 "오늘의 씨앗" 위젯을 설계했다. **지금 데이터는 그 전제와 다르다.**

```
총 논문        446편 (fields.js WIKI.INDEX)
정리 완료      446/446 (100%)   ← graph.json stats.written
성장 단계      evergreen 383 (86%) · growing 63 (14%) · sprout 0 · seed 0
분야           21개 (그룹 3개: 기반 2 · 모달리티·응용 14 · 가로지르는 관심사 5)
트랙           70개, 전부 1편 이상 보유 (빈 트랙 0개)
트랙 중 1~2편뿐인 곳  14개 (아래 5절)
```

**seed(씨앗)가 0편이다.** "오늘의 씨앗 🌱" 위젯, 씨앗 페이지 안내 문구, `note:no` 검색 필터, 완성률 배지 — 이 전부가 "아직 안 쓴 논문이 있다"는 전제로 설계됐는데 지금은 쓸 대상이 없다. 코드는 이미 `seeds.length===0` 분기를 정상적으로 처리한다(`widgetRow()`의 "씨앗 없음 — 전부 정리됨 🎉"). 즉 **디지털 가든의 "빈 칸" 스토리는 이번 개편에서 폐기하는 게 아니라 다른 층위로 옮겨야 한다** — 4절·5절에서 다룬다.

이 문서는 이 실측을 기준으로 브리프 §5의 다섯 질문에 다시 답한다.

## 1. 현재 홈 진단 (실측, `python3 -m http.server`로 렌더링해 확인)

홈은 위에서부터: 헤더(브랜드·검색·테마) → 헤드라인 1문단 → 위젯 3개(이어보기/최근 갱신/오늘의 씨앗) → 그룹 3개 × 필드 카드 21장 → `<details>`로 접힌 전체 계보도. `js/wiki/app.js`의 `viewHome()`/`widgetRow()`/`cardFor()` 기준.

| # | 질문 | 몇 초 만에 답되나 | 왜 안 되는가 |
|---|---|---|---|
| 1 | 여기 뭐가 있나 (규모·범위) | **3~5초, 부분적으로만** | 헤드라인이 "전체 446편 중 지금까지 446편이 정리됐습니다"라고 즉시 말해준다. 그런데 "지금까지 ○○편이 정리됐습니다"라는 문장 자체가 **진행 중인 프로젝트체**인데 실제로는 100%라 어색하고, 정작 "범위"(21개 분야가 뭘 아우르는지, 시대가 어디부터 어디까지인지)는 21장의 카드를 다 읽어야 감이 온다 — 1440×900 첫 화면엔 카드 2장(기반 그룹)만 보이고 19장은 스크롤해야 나온다. |
| 2 | 어디서 시작하나 (첫 방문자 진입로) | **답 안 됨** | 홈 어디에도 "이것부터 읽으라"는 안내가 없다. 위젯 3개는 전부 **돌아온 사용자**(이어보기) 또는 **저자 본인**(오늘의 씨앗) 대상이고, 첫 방문자는 21장의 동등한 카드 중 아무거나 골라야 한다. 446편·70개 트랙 앞에서 각자 알아서 카드를 클릭하다 분야 페이지에서 또 트랙 3~6개, 논문 다시 여러 편 — 진입 비용이 크다. |
| 3 | 내가 보던 게 뭐였나 (재방문 이어보기) | **1~2초, 됨** | "이어보기" 위젯이 `localStorage` 기반으로 즉시 동작(실측 화면엔 방문 기록이 1건뿐이라 "Transformer · 2017" 한 줄만 뜬다 — 정상 동작). 유일하게 잘 작동하는 블록. |
| 4 | 이 분야는 어디까지 채워졌나 (빈 칸의 정직함) | **답이 거짓으로 보임** | 카드마다 "노트 N/N편 정리됨" + 진행바가 있는데, 실측하면 **21장 전부 100%, 진행바 전부 꽉 참**. 브리프가 원한 "빈 칸이 정직하게 보인다"는 정반대로, 지금은 진행바라는 장치 자체가 정보량 0인 장식이 돼 있다. "가로지르는 관심사" 그룹의 `agent`(추론·도구·검색, UX-SPEC이 예전에 0/9로 지목했던 곳)조차 지금은 16/16 — 완전히 다른 분야가 돼 있다. |
| 5 | 무엇이 무엇에서 나왔나 (계보 그래프로) | **10초 이상 + 클릭 1회, 사실상 실패** | 전체 계보도는 페이지 **맨 마지막**, `<details>`로 **기본 접힘**. 21장 카드를 전부 스크롤해서 지나쳐야 `<summary>`가 나오고, 거기서 한 번 더 클릭해야 펼쳐진다. 브리프 원문이 "가장 핵심은 계보 그래프다. 책장은 계보로 들어가는 입구이지 대체물이 아니다"라고 명시했는데, 지금 화면은 정확히 반대로 **책장(카드) 21장이 홈의 90%를 차지하고 계보 그래프는 부록 취급**당하고 있다. |

부수 발견:
- "최근 갱신" 위젯의 3건이 전부 `2026-09-10`(오늘) — `graph.json`을 다시 빌드한 날짜가 찍힌 것으로, "최근에 실제로 공들인 논문"이 아니라 "빌드 스크립트가 마지막으로 건드린 순서"에 가깝다. 446편이 전부 같은 날 재생성됐다면 이 위젯은 재방문자에게 의미 있는 신호를 못 준다.
- 책장(책등) 은유는 브리프의 핵심 개념인데 **현재 홈 어디에도 존재하지 않는다.** 지금 있는 건 분야 단위 요약 카드 21장이지 논문 446권의 책등이 아니다. 즉 이번 개편은 "책장을 줄이는" 문제가 아니라 "책장을 처음 만들면서 동시에 계보 그래프를 밀어내지 않는" 문제다.

## 2. 섹션 순서와 비중

브리프 §5의 우선순위(무엇이 가장 먼저 답돼야 하는가)를 그대로 세로 순서에 반영한다. **원칙: 위로 갈수록 "지금 이 사람에게 즉시 유용한 것", 아래로 갈수록 "탐색·증명용".**

```
1. 헤더 (고정)                                    "규모"의 상시 배지
2. 히어로 — 한 줄 헤드라인 + 핵심 숫자 3개         Q1 (즉답)
3. 개인화 스트립 — 이어보기 · 시작 경로 · 랜덤 한 편   Q2, Q3 (같은 줄)
4. 책장 — 분야 단위, 접혀서 시작                    Q1 (규모의 "본문"), Q4
5. 계보 그래프 — 전체, 항상 펼쳐진 채로 시작         Q5 (핵심)
```

높이 비중(1440×900 기준, 스크롤 총량 대비):

| 섹션 | 세로 비중 | 첫 화면(above the fold) 포함 여부 |
|---|---|---|
| 헤더 | 3% (고정 64px) | 항상 |
| 히어로 | 8% | 포함 |
| 개인화 스트립 | 10% | 포함 (접히지 않은 한 줄) |
| 책장(분야) | 35~40% | **접힌 상태로 첫 화면에 "책장 헤더 + 첫 그룹 한 줄" 정도만** — 21장 전부를 펼쳐 보여주지 않는다 (3절) |
| 계보 그래프 | 나머지 전부 | 스크롤 1~2번 안에 도달, **기본 펼침** |

지금과 가장 크게 달라지는 결정 두 가지:
1. **계보 그래프를 접지 않는다.** 지금은 `<details>` 기본 닫힘 + 맨 아래 배치. 개편 후엔 책장 섹션 바로 다음, 기본 펼침. "보조 뷰"가 아니라 브리프가 말한 "핵심"의 위상을 화면 위치로 증명한다.
2. **책장을 접는다.** 지금은 21장이 전부 무조건 펼쳐져 스크롤의 대부분(체감 60~70%)을 차지한다. 개편 후엔 3절의 방식으로 책장이 스스로를 줄인다 — 계보 그래프가 부록이 되던 자리를 책장이 대신 차지하지 않도록.

## 3. 책장 블록의 역할 — "규모와 범위"에서 멈추고 넘겨준다

브리프: "책장이 답하는 것은 '규모와 범위'이고, 그 다음 행동은 계보 그래프 아니면 분야 진입이다."

### 3.1 책장의 두 레이어

책장을 **분야 서가(선반) 레이어**와 **책등(권) 레이어**로 나눈다. 홈에는 선반 레이어만 놓고, 권 레이어는 분야 페이지(`#/f/<id>`)로 넘긴다.

- **선반 레이어 (홈)**: 21개 분야 = 21칸의 선반. 한 칸은 그 분야의 책 N권을 **책등 미니어처의 나열**로 보여준다(개별 책 클릭 가능하되, 목적은 "이 칸에 몇 권이 어떤 색·굵기로 꽂혀 있는지"라는 질감이지 낱권 정독이 아니다). 지금의 "카드 3줄 텍스트 요약"을 대체하는 것이 아니라 **카드 안에 책등 스트립을 추가**하는 것 — blurb·연도범위·트랙 수는 유지, 완성률 배지(4절에서 폐지)의 빈 자리에 책등 스트립이 들어간다.
- **권 레이어 (분야 페이지)**: 책등 하나하나가 실제 논문 링크. 트랙별로 묶여 세로 스크롤. 지금 분야 페이지의 트랙별 카드 그리드를 책등 그리드로 바꾸는 것은 이 문서 범위 밖(분야 페이지는 3.2절 UX-SPEC 소관) — 홈 IA는 "홈에서 몇 권까지 보여줄지"만 정한다.

### 3.2 홈에서 보여줄 양 — 예산

446권의 책등을 홈에 전부 그리지 않는다(브리프 4장의 DOM/이미지 예산 제약과도 직결). 규칙:

- 선반(분야 카드) 하나당 **책등 미니어처 최대 12개**만 렌더링, 나머지는 `그 외 N권`으로 숫자만 표시(책등을 그리지 않음 = DOM 노드 절약). 12개는 연도 균등 샘플링(가장 이르게 1권, 가장 최근 1권, 중간을 등간격으로) — "이 분야가 몇 년도부터 몇 년도까지 왔는지"가 선반만 보고 짐작되게 한다. 백링크 상위로 뽑지 않는 이유: 상위권 뽑기는 "핵심 논문 랭킹"이라는 다른 질문이고, 선반의 역할은 시간축 위 밀도 감각이다.
- 21칸 선반 전체가 첫 화면에 안 보이는 게 정상이다 — **그룹 헤더 3개는 항상 보이되, 그룹 하나는 기본적으로 접혀 있다.** 그룹 접기 상태 제안: `기반`(2분야·22편, 가장 작음) 펼침 → `모달리티·응용`(14분야·289편, 절반 이상) 접힘 요약 한 줄만 → `가로지르는 관심사`(5분야·135편) 접힘. 이렇게 하면 21장을 무조건 다 펼쳐 스크롤을 잡아먹던 지금 구조에서 벗어나, "책장이 있다는 감각 + 원하면 펼친다"는 절제로 바뀐다. (전체를 항상 펼치는 지금 방식은 2.4절의 실측처럼 첫 화면부터 책장이 화면을 다 먹는 원인이었다.)
- 선반 칸 클릭(카드 클릭) = 분야 페이지 이동(기존과 동일, 변경 없음). 개별 책등 클릭 = 논문 페이지 직행(신규, 홈에서 분야를 거치지 않고 바로 한 편으로 들어가는 지름길).

### 3.3 다음 행동으로의 전환

책장 섹션의 마지막 요소는 **선반이 아니라 전환 문구 한 줄**로 끝낸다. 예:
> "21개 분야, 446편 — 어디서 왔는지 궁금하면 아래 계보 그래프로, 한 분야를 깊게 보고 싶으면 위 칸을 클릭하세요."

이 문장이 곧 책장→계보 그래프 사이의 유일한 연결부이며, 브리프가 요구한 "전환 설계"의 실체다. 화면상으로는 책장 그룹 3개 렌더링이 끝나는 지점에 얇은 구분선 + 이 한 줄 + 계보 그래프 섹션 헤더가 바로 이어진다(중간에 다른 위젯을 끼워 넣지 않는다).

## 4. 처음 온 사람의 진입로 — "여기서 시작하세요"

### 4.1 데이터 근거

`transformer`가 이 위키의 명백한 중심이다(백링크·자식 수 실측):

| slug | 연도 | 백링크(in) | 계보상 자식 수 | 비고 |
|---|---|---|---|---|
| transformer | 2017 | **87** | **48** | 전체 1위, 부모 3개(`bahdanau`·`layernorm`·`resnet`)가 이미 nlp/foundations/vision 세 분야에 걸쳐 있음 — 명실상부한 교차점 |
| bert | 2018 | 67 | 36 | transformer의 첫 대분기(사전학습 인코더) |
| gpt3 | 2020 | 62 | 46 | transformer의 둘째 대분기(스케일링) |
| clip | 2021 | 39 | 19 | vit + transformer 합류점(멀티모달) |
| resnet | 2015 | 32 | 24 | transformer의 부모, transformer 이전 시대의 허브 |
| instructgpt | 2022 | 30 | 10 | gpt3 계열의 정렬 분기 |
| vit | 2020 | 29 | 13 | transformer가 비전으로 건너간 지점(resnet+transformer 합류) |

### 4.2 추천 경로 — "AI 위키 첫 걸음" 7편

연대순으로 읽으면서 **분기(transformer에서 두 갈래) → 합류(clip) → 최신 정렬(instructgpt)**을 실제로 겪도록 고른 순서. 전부 위 표의 실측 최상위권에서만 골랐다 — "저자가 좋아하는 논문"이 아니라 "이 위키 안에서 가장 많이 참조되는 논문들의 최단 이야기 경로".

1. `resnet` (2015) — Transformer 이전, 비전의 정점이자 Transformer의 부모
2. `transformer` (2017) — 이 위키 전체의 중심(백링크 87, 자식 48)
3. `bert` (2018) — 첫 번째 분기: 사전학습
4. `gpt3` (2020) — 두 번째 분기: 스케일링
5. `vit` (2020) — 세 번째 분기: 비전으로 건너감(resnet+transformer 합류)
6. `clip` (2021) — 합류점: vit와 transformer가 멀티모달에서 만난다
7. `instructgpt` (2022) — 최신 분기: 정렬(alignment)

이 순서 자체가 "분기점과 합류점을 스스로 식별한다"는 UX-SPEC S2 시나리오의 축소판이다 — 계보 그래프를 처음 보기 전에 손으로 한 번 걸어보게 한다.

### 4.3 화면 배치

개인화 스트립(2절)의 좌측 1/3. `localStorage`에 방문 기록이 **없는** 최초 방문자에게는 "이어보기" 자리에 **이 경로가 대신** 노출된다(이어보기와 시작 경로는 상호 배타적 — 방문 기록이 생기는 순간 시작 경로는 스트립에서 빠지고 이어보기로 교체된다. 완전히 사라지진 않고 책장 섹션 상단에 "처음이신가요? 7편 코스" 링크 한 줄로 축소되어 남는다).

- 카드가 아니라 **가로 스텝 리스트**로: `resnet → transformer → bert → gpt3 → vit → clip → instructgpt` 를 화살표로 연결된 7개의 작은 pill로 배치, 지금 안 읽은 것과 읽은 것을 `localStorage`의 방문 기록으로 구분 표시(체크마크). 이렇게 하면 이 목록 자체가 "계보"라는 개념을 홈에서 미리 한 번 시연하는 역할도 겸한다 — 4절이 5절(계보 그래프)의 예고편이 된다.

## 5. 빈 칸의 정직한 표현 — 무엇이 진짜 비어있는가

0절 실측대로 **분야 단위 완성률은 더 이상 정직한 신호가 아니다**(21/21이 100%). 그래서 "빈 칸"을 보여주는 층위를 바꾼다.

### 5.1 폐기: 분야 카드의 완성률 배지·진행바
`cardFor()`의 "노트 N/N편 정리됨" + `<div class="completion">` 진행바를 **홈 카드에서 제거**한다. 정보량이 0인 채로 21번 반복되는 텍스트/DOM만 늘리고 있다(브리프 4장의 DOM 예산과도 충돌). 자리에는 3.1절의 책등 스트립이 들어간다.

### 5.2 대체 신호 ① — growing 63편 (14%)
`stage:growing`은 "쓰긴 썼지만 rich 섹션(수식·숫자로 보기·딥다이브 등)까지는 못 채운" 논문 63편이다. 이게 지금 진짜 "자라는 중"인 콘텐츠다. 홈에는 분야별 배지 대신 **전체 스트립에 숫자 하나만**: "성장 중인 노트 63편 →" 링크 하나(클릭 시 검색 팔레트가 `note:yes stage:growing` 같은 필터로 열려 그 63편 리스트로 이동, UX-SPEC 3.4의 필터 문법 그대로 재사용 — 새 화면을 만들지 않는다). 히어로 문장도 "446편 모두 정리됐고, 그중 63편은 아직 자라는 중입니다"로 바꿔 "100%인데 왜 씨앗 위젯이 있냐"는 모순을 없앤다.

### 5.3 대체 신호 ② — 트랙 밀도(1~2편뿐인 곳 14개)
분야는 전부 채워졌지만 **트랙 단위로는 여전히 편차가 크다**(실측):

```
foundations/data(데이터·벤치마크) 1편 · recsys/cf(협업필터링) 1편 · code/agent(코드 에이전트) 1편 · privacy/fed(연합학습) 1편
generative/threeD · rl/world · graph/embed · graph/expressive · recsys/seq · ir/index · code/bench · science/math · data/synth · privacy/dp — 각 2편
```

이건 책등 스트립(3.2절)에서 **자연스럽게** 드러난다 — 책등 12개 이하인 칸은 애초에 성기게 보인다. 별도 배지를 추가하지 않는다(트랙 단위 배지까지 21×70개를 홈에 얹으면 과잉이다 — 6절 "축이 많은 게 좋은 게 아니다"와 같은 이유). 트랙 밀도는 분야 페이지에서 더 세밀하게 다룰 문제로 남긴다.

### 5.4 "최근 갱신" 위젯 — 조건부 폐기
`mtime`이 실측상 전부 `2026-09-10`(오늘)로 몰려 있어 지금은 "최근"이라는 말이 무색하다. `build-graph.js`를 다시 돌린 시점의 파일시스템 mtime 전체가 한 번에 갱신됐기 때문으로 보인다(git mtime과 무관하게 재생성 시 전부 touch됨). **권고**: `mtime`을 파일시스템이 아니라 git 커밋 로그(`git log -1 --format=%cd`)에서 뽑도록 `build-graph.js`를 고치기 전까지는 이 위젯을 개인화 스트립에서 숨긴다(UX-SPEC 3.1이 이미 "추가되지 않으면 위젯 자체를 숨긴다"고 명시한 조건 그대로 적용). 이 수정은 `tools/build-graph.js` 소관이라 이 문서 범위 밖이지만, 홈 IA 결정으로 명시해 둔다: **신뢰 못 할 mtime을 보여주는 것보다 위젯을 안 보여주는 게 낫다.**

## 6. 필터 · 정렬 — 홈에는 축 하나만

축 후보(분야·연대·성장단계·태그) 중 **분야 하나만** 홈에 남긴다.

| 축 | 홈에 두는가 | 이유 |
|---|---|---|
| 분야 | **둠** — 책장의 그룹 접기/펼치기(3.2절), 계보 그래프의 필드 칩(기존 유지) | 21개 선반이라는 구조 자체가 이미 분야축이다. 별도 필터 UI를 얹을 필요가 없다 — 책장 자체가 필터의 시각화다. |
| 연대 | **뺌** | 연대는 각 선반의 책등 스트립 안에서 왼쪽(오래됨)→오른쪽(최근)으로 이미 표현된다(3.2절 균등 샘플링). 별도 연대 슬라이더는 계보 그래프의 x축과 중복되는 축을 홈에 두 번 놓는 것 — 계보 그래프에서 하면 된다. |
| 성장 단계 | **뺌 (링크 하나로 대체)** | 5.2절대로 "성장 중인 노트 63편" 링크 하나로 충분하다. seed/sprout가 0인 지금, `stage` 필터 토글 UI(예: 3-state 스위치)를 홈에 두면 대부분 evergreen만 걸러지는 뻔한 결과를 보여주는 조작 비용만 든다. 검색 팔레트의 `stage:` 문법(UX-SPEC 3.4)은 그대로 살아있으니 필요한 사람은 거기서 쓰면 된다. |
| 태그(method_tags) | **뺌** | UX-SPEC 2.5가 이미 P2로 보류(446편 전체에 태그 부여가 안 된 상태). 홈 설계에서 재론하지 않는다. |

**원칙**: 홈은 "필터링하는 화면"이 아니라 "다음 화면(분야 페이지·논문 페이지·검색 팔레트)으로 넘겨주는 화면"이다. 진짜 필터 조합(field×track×year×stage, UX-SPEC 2.4)은 전부 커맨드 팔레트 몫으로 남기고, 홈에는 그 팔레트로 가는 문(검색창, 6.1절 신설 항목 아래 "성장 중인 노트" 링크) 두 개만 둔다.

## 7. 좁은 화면 (<1100px, 모바일)

기존 CSS(`css/wiki.css`)의 유일한 기존 브레이크포인트가 `1100px`(좌측 nav-tree 접힘)이라 이를 그대로 재사용한다.

### 7.1 1100px 미만 (태블릿 폭)
- 개인화 스트립: 3열 → 세로 스택 2단(이어보기/시작경로 묶음이 위, 성장 중 링크는 텍스트 한 줄로 축소).
- 책장: 선반 카드 2열 → **1열**. 책등 스트립의 미니어처 개수를 12개 → 6개로 줄인다(칸 폭이 좁아지므로).
- 계보 그래프: 가로 스크롤 컨테이너는 유지(기존 `zoomToolbar()`/그래프 줌 로직 그대로), 세로 높이만 뷰포트에 맞춰 축소.

### 7.2 모바일 (<600px) — 무엇을 버리는가
- **책등 미니어처를 버린다.** 폭이 6개조차 의미 있게 못 그릴 정도로 좁아지면(대략 380px 이하) 선반 카드는 지금처럼 텍스트 요약(blurb·논문 수·연도범위·트랙 수)만 남기고 책등 스트립은 렌더링하지 않는다 — "은유를 줄이는 것이 정답"(브리프 4장)을 문자 그대로 적용. 대신 카드 우측에 숫자만("42편") 크게 남긴다.
- **시작 경로 7편 pill을 가로 스크롤 1줄로.** 스텝 리스트가 세로로 풀리면 화면을 다 먹으므로, `overflow-x:auto`의 가로 스와이프 한 줄로 유지(터치 스크롤 자연스러움, 신규 컴포넌트 아님 — 기존 `graph-viewport`와 같은 패턴 재사용).
- **그룹 접기 기본값을 더 공격적으로.** 데스크톱은 그룹 3개 중 1개만 접혀 있지만, 모바일은 **3개 다 접힌 채 시작**(그룹 헤더 3줄 + "펼치기"만 첫 화면에 보임) — 손가락 스크롤 비용이 마우스 스크롤보다 크기 때문.
- **계보 그래프는 버리지 않는다.** 대신 기본 펼침 대신 **모바일에서만 기본 접힘 + "계보 그래프 보기" 버튼**으로 되돌린다(작은 화면에서 SVG 그래프를 강제로 펼치면 그 자체로 스크롤 지옥이 되므로) — 단, 지금처럼 맨 끝 부록이 아니라 책장 바로 다음 자리는 지킨다. "핵심이지만 좁은 화면에서는 사용자가 원할 때 편다"는 것과 "화면 맨 끝에 처박아 존재감을 지운다"는 것은 다르다.

## 8. 와이어프레임

`design/mock/home-wire.html` — 데스크톱(≥1100px) / 태블릿(700~1099px) / 모바일(<700px) 3단 와이어프레임을 정적 HTML(회색조 박스, 실제 카피 일부 반영)로 만들었다. 브라우저에서 폭을 줄여가며 실제 리플로우를 확인할 수 있다(반응형 CSS 포함, 목업이므로 실제 토큰/컴포넌트 클래스는 쓰지 않음).

핵심적으로 이 목업이 증명하는 것: **계보 그래프가 스크롤 2~3회 안에 도달**하고 **기본적으로 펼쳐진 상태**라는 것, 그리고 **책장이 21장을 강제로 펼치지 않고 그룹 접기로 스스로 줄어든다**는 것 — 이 두 가지가 지금 홈과 개편안의 핵심 차이다.
