# FE 기술 노트 — 현재 구현이 지원 가능한 것 / 제약

작성자: 프론트엔드 구현 담당. UX-SPEC.md · DESIGN-SYSTEM.md 가 나올 때까지의
기술적 기반 정리. 큰 리라이트는 보류하고 이 문서만 우선 공유합니다.

## 추가: GRAPH-INTERACTION.md 구현 후 — 줌/팬·필터와 선택의 상호작용

`GRAPH-INTERACTION.md` 도착 후 `js/wiki/app.js`에 `wireGraphSelection()`을
구현하면서, 요청받은 "줌/팬·필터와 선택이 같이 동작할 때" 처리를 아래처럼
정리했습니다(문서에 명시가 없어 합리적으로 판단한 부분):

- **줌/팬 중 선택 유지 — 별도 코드 없이 자연히 됨.** `wireZoom()`은 `<svg>`의
  `width`/`height` 속성만 바꾸고 DOM 노드를 다시 만들지 않습니다.
  `wireGraphSelection()`은 클릭할 때마다 `svg.querySelectorAll('.node[data-slug]')`
  로 그 시점의 실제 DOM을 다시 읽으므로, 줌으로 크기만 바뀐 뒤에도 같은
  노드 요소를 그대로 찾아 클래스를 토글합니다. 실제로 ResNet을 선택한 채
  줌아웃(100%→69%)해서 강조·카드가 그대로 유지되는 것을 확인했습니다.
- **필터(홈 분야 칩)를 바꾸면 선택은 자동으로 해제됩니다.** 칩을 누르면
  `viewHome()`을 통째로 다시 호출해 `app.innerHTML`을 새로 씁니다 — 이전
  DOM(과 거기 걸려 있던 `wireGraphSelection`의 클로저 상태)이 통째로
  버려지고, 새 DOM에는 아무 노드에도 `sel-*` 클래스가 없는 초기 상태로
  다시 그려집니다. 별도의 "선택 해제" 호출을 추가할 필요가 없었습니다 —
  UX-SPEC 9절이 요구한 동작과 결과적으로 일치합니다.
- **선택된 노드가 필터로 화면에서 사라지는 경우도 위와 동일하게 처리됩니다**
  (재렌더링 자체가 선택 상태를 지우므로, "카드만 남고 강조 대상이 없는"
  상태는 애초에 발생하지 않습니다).
- 이 처리 방식(재렌더링에 선택 상태 정리를 맡기는 것)은 로컬 그래프(논문
  페이지)·분야 그래프에도 동일하게 적용됩니다 — 페이지를 이동하면
  `route()`가 뷰 함수를 다시 부르므로 마찬가지로 자연히 초기화됩니다.

## 1. 데이터가 실제로 주는 것

`content/fields.js` 의 `WIKI.INDEX` 각 행:
`[slug, year, 원제, 통칭, field, track, parents[]]`

여기서 자동으로 나오는 것:
- **부모 링크** = `parents` 배열 그대로.
- **자식 링크(=백링크)** = `W.childrenOf(slug)` (core.js에 이미 있음) — `parents`에
  자신을 포함하는 다른 모든 논문을 역인덱싱한 것. **단, 이건 "인용"이 아니라
  "계보 인덱스에 명시적으로 등록된 직접 선행 관계"** 다. 논문 본문(`content/papers/*.js`)
  안에서 `[텍스트](#/p/slug)` 형태로 만든 **본문 내 위키링크는 INDEX에 없다.**
  즉 지금 "백링크"는 두 종류가 섞일 수 있다:
  1. INDEX 기반 계보 백링크(항상 가능, 이미 구현됨 — `lineage()`)
  2. 본문 위키링크 기반 백링크(Obsidian이 하는 진짜 백링크) — **본문을 파싱해야
     알 수 있다.** 논문은 150개 중 74개만 파일이 있고 lazy-load 대상이라,
     "이 논문을 링크한 다른 모든 논문"을 계산하려면 **전체 74개(→150개) 파일을
     한 번은 다 읽어야 한다.** 이건 "열 때만 로드"라는 계약과 정면 충돌한다.

  **대안(제약 안에서 가능한 방법):**
  - (a) 빌드 타임이 없으므로, **정적 사전 계산 산출물**을 만드는 방법이 있다 —
    `tools/` 아래에 Node 스크립트를 추가해 `content/papers/*.js` 를 전부 읽고
    (이건 빌드 도구가 아니라 "저장소에 커밋되는 정적 JSON 생성 스크립트"이며
    브라우저에서 실행되지 않으므로 "빌드 도구 도입 금지" 제약과 다른 층위다)
    `content/backlinks.json` 같은 파일을 만들어두면, 브라우저는 그 JSON 하나만
    읽으면 된다. **이 방법은 `content/` 아래에 파일을 추가하는 것**이라 지금
    다른 에이전트가 `content/papers/*.js` 를 동시에 쓰고 있는 상황과 충돌 위험이
    있다 — 새 파일 하나 추가하는 정도면 안전하지만, 언제 재생성할지(수동? 매
    배포 전 1회?) 정해야 한다.
  - (b) 그냥 **INDEX 기반 백링크만 "백링크"로 부르고**, 진짜 본문 링크 그래프는
    페이지를 실제로 연 적이 있을 때만(세션 캐시) 점진적으로 채워 넣는
    "알려진 만큼만 보여주는" 방식으로 타협. 완전하지 않다는 걸 UI로 정직하게
    표시(예: "지금까지 열어본 문서 기준").
  - 셋 중 하나를 스펙에서 골라야 한다. **권장은 (a)** — 정확하고, 계약 위반이
    아니고, 구현 비용이 낮다(빌드 없는 사이트에 흔한 패턴: 커밋된 산출물).

- **로컬 그래프(논문 페이지의 미니 그래프)**: parents/children 1~2홉은 META만
  으로 즉시 그릴 수 있다(본문 로드 불필요). **본문 위키링크까지 포함한 로컬
  그래프는 위 (a)/(b)와 동일한 제약을 받는다.**

- **태그**: 지금 스키마에는 태그 개념이 없다. `field`/`track`이 사실상 유일한
  분류축이다. Tana처럼 다축 태그·관계 필터를 원한다면:
  - `WIKI.paper({...})` 에 **선택적** 필드(`tags:['peft','attention',...]` 등)를
    추가하는 건 계약상 허용된다("새 필드는 선택적으로만"). 하지만 **74개 기존
    파일에는 없으므로, 태그가 없는 논문이 압도적으로 많은 상태로 UI를 설계해야
    한다.** 전면적인 태그 필터 UI를 만들어도 당장은 대부분 "태그 없음"이 뜬다.
  - 코스트가 더 싼 대안: `content/fields.js` 의 `field`+`track` 조합을
    "구조적 태그 두 개"로 취급해 태그 칩 UI를 먼저 그 위에 올리고, 자유
    태그는 나중 단계로 미룬다.

## 2. Lazy 로딩 제약이 실제로 막는 것

- `W.load(slug)` 는 `<script>` 태그를 그때 주입해서 `content/papers/slug.js`
  를 받는다. **HEAD 요청(본문은 안 받고 존재/크기만 확인)은 이 계약과 별개다** —
  이건 브라우저 native fetch로, "150개를 미리 다 받는" 것과 다르다. 그래서:
  - 논문이 "노트 없음/있음"인지는 파일 목록을 정적으로 커밋 시점에 알 수도
    있고(빌드 스크립트로 `content/papers/` 디렉터리를 스캔해 `WIKI.HAS` 같은
    존재-집합을 `fields.js` 와 별도 파일로 만들어도 됨), 런타임에 HEAD로
    확인해도 된다. **HEAD 방식은 GitHub Pages(정적 호스팅)에서도 동작**하고
    본문을 받지 않으므로 계약 위반이 아니라고 판단한다 — 다만 150개 동시 HEAD는
    과할 수 있어 "현재 화면에 보이는 항목만" 확인하는 걸 권장.
  - "성장 단계(seed/growing/mature)"를 **본문 분량**으로 정의하려면(예:
    AUTHORING.md 가 요구하는 5~9KB 기준) HEAD 응답의 `Content-Length` 헤더로
    대략 추정 가능 — 본문을 안 받고도 크기를 안다. 다만 이건 "정확한 분량"이
    아니라 "파일 바이트 수" 근사치임을 UX 카피에서 밝혀야 오해가 없다.

- 페이지를 한 번 열면 `W.PAPERS[slug]` 에 캐시되어 재방문 시 재요청 없음(이미
  구현됨). 세션 중 "열어본 논문 목록"을 저장해두면 (b)식 점진적 백링크/최근
  방문 등 Tana류 기능에 재사용 가능.

## 3. 그래프 레이아웃(`js/wiki/graph.js`)의 한계

- 지금은 "존재하는 연도만 등간격 압축 + 트랙별 레인 + 레인 안에서 겹치면
  다음 행으로" 방식. 문제는 **레인 하나에 논문이 몰리는 연도가 있으면 그 레인만
  세로로 길어지고, 전체 폭은 연도 개수 × 142px 로 선형 증가**한다는 것 —
  분야 하나가 30~40년 폭에 걸쳐 있으면 필연적으로 넓어진다(현재 `overflow-x:auto`
  로만 대응).
- 실질적으로 고를 수 있는 방향(스펙에서 택 1, 혹은 조합):
  1. **줌/스케일 컨트롤**만 추가(내용은 그대로, `transform:scale` 로 축소) —
     구현 비용 가장 낮음, 정보 밀도는 그대로 유지.
  2. **연도를 10년 단위로 묶어 열(column)로** 바꾸고 같은 10년 안에서는
     칩처럼 좁게 배치 — 폭을 크게 줄이지만 "정확한 연도" 축이라는 정체성을
     잃는다.
  3. **트랙 접기/펼치기**(레인 헤더 클릭 시 그 레인만 collapse) — 폭은 그대로,
     세로 스크롤 부담을 줄임(가로 문제는 그대로).
  4. **분야 페이지에서 트랙 필터 칩**으로 한 번에 1~2개 트랙만 그리기 — 폭은
     줄지 않지만 "동시에 보이는 상자 수"가 줄어 체감 가독성은 오른다.
  현재 코드 구조상 1과 4는 반나절 이내로 구현 가능. 2는 데이터 표현(연도
  축)을 바꾸는 것이라 캡션·범례도 같이 바뀌어야 한다.

## 4. 다이어그램 렌더러(`js/wiki/diagram.js`)

- 스키마(타입 이름·필드)는 고정, 이미 150편 중 74편의 데이터가 이 스키마로
  작성돼 있어 **타입을 늘리거나 필드명을 바꾸면 기존 데이터가 깨진다.**
  타이포/색/간격/화살표 같은 시각 규칙은 자유롭게 바꿀 수 있다 — DESIGN-SYSTEM.md
  에서 다이어그램 색상 토큰·스트로크 굵기·폰트 크기·박스 padding 등을 정해주면
  그대로 반영 가능.
- `wrap()` 함수가 텍스트를 최대 3줄로 자르는데, 한글은 공백 기준 word-wrap이
  거의 안 먹혀서(한글은 띄어쓰기가 영어보다 드묾) 긴 한글 라벨이 잘리는 경우가
  있다. 글자 단위 wrap으로 바꾸는 게 나을 수 있음 — 스펙에서 다이어그램 라벨
  최대 길이 가이드가 있으면 좋겠음.

## 5. 지금 확인된 저위험 이슈 (스펙 대기 중에도 바로 고쳐도 되는 것들)

- 콘솔 에러: 현재 실행 확인 필요 (아직 브라우저로 열어보지 않음 — 스펙 도착
  전까지 진단만 하고 손대지 않을 예정).
- 접근성: 검색 input에 `aria-label` 없음, 테마 토글 버튼(`◐`)에 텍스트 대체
  없음, 다이어그램 SVG에 `role="img"`/설명 없음, `.node`/`.pill`/`.card` 가
  `div`+`data-go` 클릭으로만 동작해 **키보드로 논문 카드/그래프 노드에 접근할
  수 없음**(탭 포커스 불가, 스크린리더 인지 불가).
- 반응형: `.paper` 그리드가 980px 미만에서 TOC(`.side`)를 완전히
  `display:none` 처리 — 모바일에서 목차 자체가 사라짐(대안 없음). 검색 결과
  드롭다운(`.results`)이 420px 고정 폭이라 좁은 화면에서 넘침.
- `js/wiki/*.js` 전부 `node --check` 통과 확인함(현재 상태 기준, 문제 없음).

## 6. 스펙 작성 시 참고할 결정 포인트 (제가 임의로 못 정하는 것)

1. 백링크를 (a) 빌드-스크립트 산출물 방식으로 할지 (b) 세션 점진적 방식으로
   할지, 혹은 1단계는 (b)로 가고 나중에 (a)로 갈지.
2. 태그를 지금 당장 스키마에 넣을지(선택적 필드로), 아니면 field/track만으로
   1차 출시할지.
3. 계보도 폭 문제 해법으로 줌/트랙필터/10년묶음/레인접기 중 무엇을 채택할지
   (조합 가능, 홈/분야 페이지에서 다르게 가도 됨).
4. "성장 단계" 3단계 기준을 파일 크기 근사치로 표시해도 되는지, 아니면
   본문에 `stage:` 같은 선택적 메타 필드를 저자가 직접 적게 할지.
