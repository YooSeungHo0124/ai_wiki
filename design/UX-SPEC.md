# UX / IA 스펙 — AI 논문 계보 위키

작성자: UX/IA 디자이너 · 대상: 프론트엔드 구현자, 비주얼 디자이너
범위: 구조·흐름·상태·규칙만 정의한다. 색·폰트·간격 등 시각 스타일은 비주얼 디자이너가 정한다.

전제 데이터 — **두 축을 구분해서 쓴다**:
- `content/fields.js` — `WIKI.FIELDS`(분야·트랙 정의), `WIKI.INDEX`(150행, slug·연도·원제·통칭·분야·트랙·**parents**). `parents`는 저자가 직접 지정한 **계보(lineage)** — "이 논문이 지적으로 딛고 선 것"이다.
- `content/graph.json` — `tools/build-graph.js`가 `content/papers/*.js` 150개를 파싱해 **사전 계산**한 정적 인덱스. 부팅 시 한 번만 로드하면 되고(66KB), lazy-load 계약(논문 본문은 열 때만 fetch)과 충돌하지 않는다. 논문 노트를 고치면 재실행해야 갱신된다. 스키마:
  ```
  papers[slug] = {
    stage: 'seed'|'sprout'|'growing'|'evergreen',   // 5장
    bytes, sections: ['math','numbers','links','deep',...],
    out: [slug,...],   // 본문 위키링크가 실제로 가리키는 문서 (나가는 언급)
    in:  [slug,...],   // out의 역인덱스 (백링크 = 들어오는 언급)
    tags: [field, track, year(문자열)],
    diagram: 'stack'|'compare'|...|null,
    extLinks: 3
  }
  stats: { total:150, written:116, byStage:{evergreen:111,growing:5,sprout:0,seed:34}, byField:{...} }
  ```
  `in`/`out`은 **본문 텍스트에 실제로 걸린 위키링크**(언급, mention)이고, `parents`(계보, lineage)와 겹치지만 **동일하지 않다** — 4장에서 이 둘을 명확히 구분해 다르게 표현한다.

현재 실측(2026-09-09, `graph.json`): 150편 중 116편(77%) 작성, evergreen 111 · growing 5 · sprout 0 · seed 34. 본문 위키링크 878개, 백링크가 붙은 문서 145/150편. 피인용(들어오는 언급) 상위 — transformer 36 · bert 21 · gpt3 20 · resnet 18 · llama 18 · clip 17 · vit 16. 분야별 편차가 크다: `vision`·`nlp`·`foundations`·`llm`·`efficiency`는 100% 작성, 반면 `rl`은 3/12, **`agent`(0/9)와 `interp`(0/10)는 통째로 씨앗밭**이다 — 이 두 분야 페이지는 "정상 상태"로 다뤄야 한다(3.2절 상태 참조).

## 1. 사용자와 사용 맥락

주인이자 주 독자는 AI를 만드는 개발자 한 명(본인). 완전한 타인 트래픽은 부수적이다. 4가지 시나리오로 설계 기준을 고정한다.

### S1. 개념 확인 — "GQA가 뭐였더라?"
- 진입: 커맨드 팔레트(`/`) → 타이핑 3~5자 → Enter. **2번의 키 조작, 0번의 마우스 클릭**으로 논문 페이지 도착.
- 종료 조건: `tldr` 한 문단을 읽고 창을 닫는다. 스크롤 없이 첫 화면에 tldr + 핵심 아이디어 제목까지 보여야 한다.
- 실패 조건: 검색 결과에 없거나(색인 누락), 페이지가 스텁이라 답을 못 얻는 것.

### S2. 계보 탐색 — "attention 개조가 어디서 갈라져서 어디로 모였지?"
- 진입: 논문 페이지의 "계보" 섹션 또는 분야 페이지의 트랙 그래프.
- 조작: 부모/자식 pill 클릭으로 그래프를 따라간다 (한 번의 클릭 = 한 홉 이동). 3~4홉을 왕복해도 "지금 내가 어디 있는지"를 잃지 않아야 한다 → 브레드크럼 + 로컬 그래프의 "현재 노드 고정" 표시로 보장.
- 종료 조건: 계보의 분기점(부모가 2개 이상)과 합류점(자식이 2개 이상)을 스스로 식별할 수 있다.

### S3. 새 논문 정리 — "오늘 읽은 논문을 위키에 넣는다"
- 진입: `content/fields.js`에 인덱스 한 줄 추가 → 사이트에서 해당 slug가 즉시 🌱 씨앗 페이지로 존재 → `content/papers/<slug>.js` 작성 → 새로고침.
- 이 스펙이 보장할 것: 씨앗 페이지가 "빈 페이지"가 아니라 **무엇을 채워야 하는지 알려주는 화면**이어야 한다(3장 참조). 작성 중간에도 필수 섹션이 채워지는 대로 바로 보여야 한다(부분 렌더링은 이미 `app.js`의 `add()` 패턴이 지원 — 빈 섹션은 자동 생략).
- 종료 조건: `node tools/check.js` 통과 + 사이트에서 육안 확인.

### S4. 공유 — "이 논문 정리 링크 하나 보내줄게"
- 진입: 주소창에서 해시 URL 복사(`#/p/lora`), 또는 페이지 내 "링크 복사" 버튼(신규, P1).
- 상대는 위키 문맥이 없는 사람일 수 있다 → 논문 페이지는 **독립적으로 완결**돼야 한다(브레드크럼으로 분야 맥락은 주되, 분야를 몰라도 tldr만으로 이해 가능해야 함 — 이미 AUTHORING.md 톤 규칙과 일치).
- 종료 조건: 상대가 클릭 한 번(브레드크럼 "전체 지도") 이내에 전체 맥락 지도로도 갈 수 있다.

## 2. 정보구조

### 2.1 위계
```
전체 (150편)
 └─ 분야 10개 (WIKI.FIELDS)                         고정, 자연어 순서 유지
     └─ 트랙 2~5개 / 분야 (WIKI.FIELDS[].tracks)     고정
         └─ 논문 (WIKI.INDEX 행)                     연도순 정렬이 기본
```
분야·트랙 순서는 `WIKI.FIELDS` 배열 선언 순서를 그대로 신뢰한다(현재도 그렇게 되어 있음 — 기초→비전→NLP→LLM→효율→생성→멀티모달→RL→에이전트→해석, "기반에서 응용으로"의 서사 순서). 새 분야/트랙 추가는 이 문서 범위 밖.

### 2.2 파생 축 (신규 데이터 없이 바로 쓸 수 있음)

`fields.js`에서 바로 나오는 것과 `graph.json`(사전 계산)에서 나오는 것을 구분해 표시한다.

| 축 | 출처 | 계산 방법 | 용도 |
|---|---|---|---|
| 연도 | fields.js | `WIKI.INDEX[1]` / `tags[2]` | 타임라인 정렬, `year:2023` 필터 |
| 분야 / 트랙 | fields.js | `[4]`/`[5]` / `tags[0..1]` | 내비 트리, 카드 그룹핑, `field:`/`track:` 필터 |
| 부모 수 (계보) | fields.js | `parents.length` | 0이면 "뿌리 논문" |
| 자식 수 (계보) | fields.js | 자기 slug를 `parents`에 담은 행 수(`W.childrenOf`) | 0이면 후속 없음, 3 이상이면 "계보상 허브" |
| 분기/합류 | fields.js | 부모 수≥2 → 합류점, 자식 수≥2 → 분기점 | 그래프 강조 |
| 교차분야 링크 | fields.js | `parents` 중 `field`가 다른 것의 수 | "이 논문은 N개 분야를 잇는다" (DETR, CLIP 등) |
| 성장 단계 | **graph.json** | `stage` 필드 (5장) | 배지, `stage:seed` 필터 |
| 피인용 수(언급) | **graph.json** | `in.length` | "핵심 논문" 랭킹, `cites:>=N` 필터 — 4장에서 계보와 구분해 다룸 |
| 언급 관계 | **graph.json** | `in`/`out` 배열 | 백링크 섹션, "이 논문을 언급한 문서" (4장) |
| 다이어그램 타입 | **graph.json** | `diagram` | `diagram:compare` 필터, 카드 아이콘 |
| 채움 섹션 | **graph.json** | `sections` (venue·authors·arxiv·math·numbers·links·deep 중 있는 것) | "숫자로 보기 있는 논문만" 같은 세부 필터(P2) |
| 같은 트랙 형제 | fields.js | `field`+`track` 동일 | "함께 읽으면 좋은" 1차 후보 (4장) |
| 공통 부모(co-citation, 계보) | fields.js | 두 논문이 `parents`를 하나 이상 공유 | "함께 읽으면 좋은" 2차 후보 (4장) |

`content/papers/<slug>.js` 파일 존재 여부 자체를 fetch로 확인할 필요가 이제 없다 — `graph.json.papers[slug].stage==='seed'`가 정확히 그 값이다. `tools/check.js`는 여전히 **검증**(오류·경고를 콘솔에 출력, CI/커밋 전 게이트) 용도로 남기고, UI가 읽는 "상태값"은 전부 `graph.json` 하나로 일원화한다 — 두 스크립트의 판정 기준이 어긋나지 않도록 `build-graph.js`의 `stage` 계산 로직이 유일한 출처다.

### 2.3 관계의 두 종류 — 계보 vs 언급 (반드시 구분)

이 위키의 성격을 정하는 결정이다. 절대 하나로 합치지 않는다.

| | **계보 (lineage)** | **언급 (mention)** |
|---|---|---|
| 출처 | `fields.js`의 `parents` (저자가 수작업으로 고른 값) | `graph.json`의 `in`/`out` (본문 위키링크를 파싱한 값) |
| 의미 | "이 논문이 지적으로 딛고 선 **직접 선행 연구**" — 큐레이션됨, 개수가 적음(대부분 1~3개) | "본문 어딘가에서 이 문서를 링크로 걸었다" — 자동 추출됨, 개수가 많을 수 있음(transformer는 36개) |
| 신뢰도 | 높음 · 의도적 | 넓음 · 부수적(문맥상 스치듯 언급도 포함) |
| 그래프 표현 | **굵은 실선 화살표**, 방향 있음(부모→자식), 전체/분야 계보도의 유일한 엣지 | 로컬 그래프에서만 **가는 점선**, 계보도 본선에는 절대 섞지 않는다 |
| 목록 표현 | pill(칩) — "이 논문이 딛고 선 것 / 이 논문 위에 선 것" (기존 유지) | 플레인 링크 리스트 + 개수 배지 — "본문에서 언급함(N) / 본문에서 언급됨(N)" |
| 개수가 많을 때 | 원래도 적어서 문제 없음 | 5개 초과 시 상위 5개만 펼치고 "+N개 더 보기" (허브 논문 대응, 4.3절) |

즉 전체 계보도·분야 계보도는 지금처럼 `parents` 기반 화살표만 그리고(변경 없음), **"언급"은 논문 페이지에만 새로 등장하는 정보**다.

### 2.4 질의 뷰 제안 (Tana식 — 자유 태그 없이 기존 축만 조합)

자유 태그(`method_tags`)는 P2로 미루고, `field × track × year × stage × diagram × 피인용수(in.length)` 조합만으로 만들 수 있는 뷰. 전부 커맨드 팔레트 필터 문법(3.4절)으로 구현 가능하며 **150편 데이터에 손 댈 필요가 없다**.

1. **다음에 쓸 논문 큐** — `stage:seed` 정렬 기준을 `in.length desc`로: "아직 노트는 없지만 다른 논문에서 가장 많이 언급된" 순. 예: cyclegan은 seed이면서 unet·gan·dcgan·pix2pix 4곳에서 언급됨 — 이런 논문을 먼저 써야 leverage가 크다. 홈 위젯 "오늘의 씨앗"(3.1)을 랜덤 대신 이 정렬로 뽑는 안도 고려할 수 있음(P1에서 결정).
2. **핵심 논문 랭킹** — 전체(또는 `field:` 한정)를 `in.length desc`로 정렬한 Top 10. "이 위키에서 가장 많이 참조되는 논문"이라는, 저자 본인도 몰랐을 사실을 드러낸다.
3. **분야 완성도 대시보드** — `stage`별 카운트를 `field:`로 쪼갠 것 (문서 서두의 실측 통계와 동일한 것을 화면으로) — `agent`/`interp`처럼 통째로 비어 있는 분야를 홈에서 바로 보이게 한다.
4. **다이어그램 형식 감사** — `diagram:compare`처럼 한 타입만 모아보기. "이 논문도 compare로 그릴 수 있었을까?" 같은 저자 본인의 작성 스타일 점검 용도.
5. **최근 흐름** — `year:>=2023` + `field:` 조합. "2023년 이후 LLM 오픈 웨이트 흐름만" 같은 질의.
6. **숨은 연결 찾기** — (P2, 구현 비용 있음) `out`에는 있는데 `parents`에는 없는 관계 = "언급은 했지만 계보로 등록 안 한 영향 관계". 저자가 나중에 `parents` 배열을 보강할지 검토하는 큐레이션 보조 도구로 유용하지만, 계산에 두 데이터를 교차해야 하므로 P2.

이 뷰들은 **별도 화면이 아니라 전부 검색/커맨드 팔레트(3.4)의 필터 조합 결과**다 — 새 페이지를 만들지 않는다.

### 2.5 확장 축 (신규 수작업 데이터 필요 — "확장" 절)

Tana식 태그·속성을 더 원하면 아래는 150편 각각에 필드를 추가해야 하므로 **P2, 선택적**이다. 지금 IA에는 포함하지 않는다.

- `method_tags`: 자유 태그 배열(예: `moe`, `contrastive`, `rlhf`) — "MoE를 쓰는 논문 전부" 같은 질의를 가능하게 하지만, 150편 전체에 태그를 부여하는 별도 작업이 필요. **결정: P2로 확정.** 2.4절의 질의 뷰 6종이 `field × track × year × stage × diagram × 피인용수`만으로 실용적 가치를 이미 충분히 낸다고 판단했다 — 자유 태그는 그 이상이 필요해질 때(예: 태그 없이는 답할 수 없는 실제 질문이 반복될 때) 재검토한다. 도입한다면 `content/papers/<slug>.js`에 `tags:['moe']` 한 줄만 추가하고 `build-graph.js`가 이를 `graph.json`에 흡수하는 방식으로 — 없는 논문은 빈 배열 취급(에러 아님, 씨앗 논문도 태그 없이 존재해야 하므로).
- `read_status`(개인용 읽음 상태) / `confidence`(내가 이해한 정도): 브라우저 `localStorage`에 `slug → 'read'|'later'` 식으로 저장하면 데이터 파일을 건드리지 않고도 개인화 가능 — **이건 파생도 확장도 아닌 "런타임 개인 상태"로 분류, P1.**

### 2.6 좌측 내비 트리 (신규, GitHub Docs 참조)

현재 사이트에는 고정 내비가 없다(홈에서 카드 클릭 → 분야 페이지만 존재). 논문/분야 페이지에 좌측 고정 트리를 추가한다.

```
▾ 컴퓨터 비전 (vision)
   ▾ CNN 백본 계보 (9)
      LeNet-5 1998
      AlexNet 2012
    ▸ 객체 탐지 (7)
    ▸ 분할 (5)
    ▸ Vision Transformer (4)
    ▸ 자기지도 학습 (5)
▸ 언어 표현 (Transformer 이전)
▸ Transformer · LLM
...
```
- 규칙: 현재 보고 있는 논문이 속한 분야만 기본 펼침, 나머지는 접힘. 트랙까지는 펼치되 논문 목록은 **현재 논문이 속한 트랙만** 펼친다(150개를 한 화면에 다 펼치면 안 됨).
- 노트 없는 논문(`stage:seed`)은 트리에서 회색 + 🌱 아이콘으로 구분(클릭은 가능, 씨앗 페이지로 이동). `agent`/`interp`처럼 분야 전체가 seed면 그 분야 노드 자체를 회색으로 표시해 "여기는 통째로 비어 있다"는 걸 트리 레벨에서 미리 알린다.
- 좁은 화면(모바일)에서는 트리를 숨기고 브레드크럼 옆 "☰" 버튼으로 슬라이드 오버레이.

## 3. 화면별 스펙

### 3.1 홈

**목적**: 전체 지도를 보여주고, "지금 무엇을 볼까"에 답한다.

```
┌───────────────────────────────────────────────────────────┐
│ [브랜드]                          [ /검색 ]        [◐테마] │
├───────────────────────────────────────────────────────────┤
│  헤드라인 + 한 줄 설명                                      │
├───────────────────────────────────────────────────────────┤
│  [이어보기]   [최근 갱신]   [오늘의 씨앗 🌱]   (신규 위젯행)│
├───────────────────────────────────────────────────────────┤
│  [카드] [카드] [카드] [카드] [카드]     ← 분야 10개, 2행    │
│  [카드] [카드] [카드] [카드] [카드]                          │
├───────────────────────────────────────────────────────────┤
│  전체 계보도 (SVG, 스크롤/줌 가능) — 6장 참조                │
└───────────────────────────────────────────────────────────┘
```

**컴포넌트**
- 분야 카드(기존 유지): 색 바, 영문명, 국문명, blurb, `논문 N편 · 연도범위 · 트랙 M개`. **추가**: 완성률 배지 — `노트 있음/전체` (파생 가능, 예: "63/150 편 정리됨"). 카드 우하단에 작은 진행 바.
- 신규 위젯 행 3개 (P1):
  - **이어보기**: `localStorage`에 남은 마지막 방문 논문 3개.
  - **최근 갱신**: `graph.json`은 현재 mtime을 담지 않으므로(파싱 결과만 있음) 이 위젯은 **`build-graph.js`에 `mtime` 필드 추가를 전제로 P1**으로 둔다. 추가되지 않으면 위젯 자체를 숨긴다(빈 상태를 억지로 채우지 않음) — 프론트엔드 구현자가 `graph.json` 확장 여부를 판단.
  - **오늘의 씨앗**: `graph.json`에서 `stage==='seed'`인 34편 중 랜덤 1편(또는 2.4절 "다음에 쓸 논문 큐" — `in.length` 내림차순 1위) + "정리하기" CTA → 씨앗 페이지로. **권고: 랜덤보다 큐 방식** — leverage가 큰 것부터 쓰게 유도하는 게 디지털 가든을 실제로 키우는 데 더 도움이 된다.
- 전체 계보도: 기존 SVG 유지, 6장의 개선안 적용.

**상태**
- 로딩: `content/fields.js`는 동기 스크립트라 사실상 즉시 — 로딩 스피너 불필요.
- 완성률 0%/100% 극단값도 카드 문구가 깨지지 않게(예: "0편 정리됨" 정상 출력).

**키보드**: `/` 검색 포커스, `↑↓` 카드 그리드 대신 검색 결과 이동(기존 유지). 카드 자체의 화살표 키 내비게이션은 P2(카드 10개뿐이라 탭 이동으로 충분).

### 3.2 분야 페이지 (`#/f/<id>`)

**목적**: 한 분야 안의 트랙별 흐름과 논문 목록.

```
┌───────────────────────────────────────────────────────────┐
│ 전체 지도 › 컴퓨터 비전                        (브레드크럼)  │
│ 컴퓨터 비전 Vision                                          │
│ blurb...                                                    │
├───────────────────────────────────────────────────────────┤
│ 트랙 그래프 (연도×트랙 레인) — 기존 유지, 6장 개선안 적용     │
├───────────────────────────────────────────────────────────┤
│ CNN 백본 계보 (9편)                    [정렬: 연도▾][보기:▾]│
│ [카드][카드][카드]...                                       │
│ 객체 탐지 (7편)                                             │
│ [카드]...                                                   │
└───────────────────────────────────────────────────────────┘
```

**추가 컴포넌트**
- 카드에 🌱/🌿/🌳/🌲 성장 배지(5장, `graph.json`의 `stage`를 그대로 씀). 지금은 없음. `agent`/`interp` 분야 페이지는 모든 카드가 🌱인 채로 정상 렌더돼야 한다(3.2절 상태 참조) — "데이터 없음 오류"처럼 보이면 안 됨.
- 정렬 토글(P1): 연도순(기본) / 계보 순서(위상정렬 — 부모가 먼저) / 미작성 우선(`stage:seed`를 `in.length` 내림차순으로 — 2.4절 "다음에 쓸 논문 큐"와 동일 로직).
- 보기 토글(P1): 카드형(기본) / 표형(제목·연도·부모수·상태를 표로, 빽빽하게 스캔할 때).

**상태**
- 트랙에 논문이 0편이면(현재는 없음이 없으니 이론상만) 해당 트랙 헤더 자체를 숨긴다(기존 로직이 이미 그렇게 함, 유지).
- **분야 전체가 seed** (현재 `agent`, `interp` — 각 0/9, 0/10): "아직 정리된 노트가 없습니다" 같은 오류성 문구를 달지 않는다. blurb·트랙 그래프·논문 카드(전부 🌱)는 그대로 다 보여준다 — 이 분야는 "고장난 페이지"가 아니라 "다음에 심을 밭"이다. 헤더에 작은 안내 배지만 추가: `이 분야는 아직 씨앗 단계입니다 · 0/9편`.

### 3.3 논문 페이지 (`#/p/<slug>`)

**목적**: 한 편을 완결적으로 이해시키고, 계보 위 위치를 보여준다.

```
┌───────────────────────────┬───────────────────────────────┐
│ [내비트리]  전체지도›분야›트랙                [목차 aside]  │
│  (접힘/     제목(국문) / 원제                               │
│   펼침)     [분야][연도][학회][저자][arXiv]  [🌲 evergreen] │
│             ──────────────────────────────                 │
│             tldr                                            │
│             [🧭 딥다이브 링크 있으면]                        │
│             1. 그 전까지의 문제                              │
│             2. 핵심 아이디어                                 │
│             3. 구조 한눈에 (다이어그램)                      │
│             4. 수식으로                                      │
│             5. 숫자로 보기                                   │
│             6. 무엇이 바뀌었나                               │
│             7. 이후로 이어진 것                              │
│             8. 흔한 오해 · 함정                              │
│             9. 계보 — 딛고 선 것/위에 선 것(pill) + 로컬     │
│                그래프 (fields.js parents 기반, 신규, 4.3)    │
│             10. 본문에서 언급함·언급됨 (신규 — graph.json    │
│                 in/out, 계보와 시각적으로 분리, 4장)          │
│             11. 함께 읽으면 좋은 (신규, 파생)                │
│             12. 더 읽기 (외부 링크)                          │
│             ‹ 이전 논문   다음 논문 ›                        │
└───────────────────────────┴───────────────────────────────┘
```

**상태 — 노트 없음 (씨앗 페이지, 5장과 연결)**
```
전체지도 › 분야 › 트랙
제목(국문) / 원제
[분야][연도]                                    [🌱 씨앗]

  이 논문의 정리 노트는 아직 없습니다.

  ┌ 계보상 위치 ─────────────────────────┐
  │ 이 논문이 딛고 선 것: [pill][pill]     │
  │ 이 논문 위에 선 것:   [pill][pill][pill]│
  └────────────────────────────────────┘

  ┌ 본문에서 언급됨 (3) ──────────────────┐
  │ unet · gan · dcgan · pix2pix           │   ← graph.json의 in, seed 논문도 존재
  └────────────────────────────────────┘

  작성 안내: content/papers/lora.js 를 만드세요.
  규격: AUTHORING.md · 예시: content/papers/transformer.js
  필수 섹션: tldr · context · ideas(3~5) · diagram · impact · legacy · pitfalls
```
씨앗 페이지도 **계보 섹션과 언급(백링크) 섹션은 보여준다** — 계보는 `fields.js`, 언급은 `graph.json`에서 이미 계산돼 있으므로 노트 파일이 없어도 존재하는 정보다(위 cyclegan 예시처럼 seed 논문도 4곳에서 언급될 수 있다 — 오히려 "먼저 써야 할 이유"를 보여주는 신호). "완전히 빈 페이지"를 만들지 않는 것이 디지털 가든 철학의 핵심.

**상태 — 로딩**: `W.load(slug)` 동안 스켈레톤(제목·메타 자리만 즉시 렌더 — `m`은 인덱스에서 이미 있으므로 head는 즉시 그릴 수 있음, 본문만 로딩 표시). 지금 코드(`viewPaper`)는 헤더까지 통째로 로딩 문구로 덮는데(`<div class="stub">불러오는 중…</div>`), **개선**: 헤더(제목/메타/브레드크럼)는 즉시 그리고 본문 영역만 스켈레톤 처리.

**키보드**
- `[` `]` : 이전/다음 논문(같은 분야 연도순, 기존 pagenav와 동일 순서).
- `g g` : 홈으로. `g f` : 소속 분야로.
- 목차 항목은 이미 앵커 링크라 클릭/탭으로 충분.

### 3.4 검색 / 커맨드 팔레트

**목적**: S1 시나리오의 유일한 진입점. 현재도 있으나(`/` → 인풋 → 결과 리스트) 이름/원제만 매칭. Tana식 파생 축 필터를 여기 얹는다.

```
┌───────────────────────────────────────┐
│ /  gqa                                │
├───────────────────────────────────────┤
│ GQA · 2023 · 효율 · 시스템             │
│ GQA: Training Generalized Multi-Query…│
├───────────────────────────────────────┤
│ MQA · 2019 · 효율 · 시스템             │
│ Fast Transformer Decoding…             │
└───────────────────────────────────────┘
```

**필터 문법 (신규, 파생 축 기반, P1)** — 출처가 fields.js인 것과 graph.json인 것이 섞여 있지만 사용자에게는 하나의 문법으로 노출한다.

| 필터 | 의미 | 출처 |
|---|---|---|
| `year:2023`, `year:>=2023` | 연도 | fields.js |
| `field:llm`, `track:attn` | 분야/트랙 | fields.js |
| `parents:0` | 뿌리 논문(계보상 시작) | fields.js |
| `children:0` / `children:>=3` | 계보상 후속 없음 / 허브 | fields.js |
| `stage:seed` / `stage:evergreen` 등 | 성장 단계 (5장 4종) | graph.json |
| `diagram:compare` | 다이어그램 타입 | graph.json |
| `cites:>=20` | 피인용 수(들어오는 언급, `in.length`) — "허브 논문" | graph.json |
| `mentions:bert` | 본문에서 bert를 언급한 문서 전부 (`out`에 bert 포함) | graph.json |
| `cited-by:bert`(alias: `linked-from:`) | bert를 언급한 문서 전부 — `mentions:`와 동일 결과, 읽기 편한 별칭 | graph.json |

- 자유어와 결합 가능: `field:vision stage:seed` → 비전 분야의 미작성 논문만. `stage:seed cites:>=2` → 2.4절 "다음에 쓸 논문 큐"를 필터만으로 재현.
- 파싱 규칙: 공백으로 토큰 분리, `key:value` 형태는 필터로, 나머지는 기존처럼 slug/title/ko 부분일치. 필터는 AND로만 결합(OR·NOT은 P2, 과설계 방지). 기본 정렬은 자유어 매칭 점수, 필터만 있을 때는 `year` 오름차순 — 단 `stage:seed`와 함께일 때만 `cites` 내림차순(작업 큐 목적이 명확하므로).

**상태**
- 결과 0건: "일치하는 논문이 없습니다" + 가장 가까운 필터 힌트(예: `field:llm` 오타 시 후보 분야명 나열).
- 필터만 있고 자유어 없음(`stage:seed` 등): 최대 12개 제한을 풀고 스크롤 가능한 전체 리스트로 전환(작업 큐 용도이므로 12개 제한은 부적절).

**키보드**: `↑↓` 이동, `Enter` 이동, `Esc` 닫기 (기존 유지). `Tab` 으로 필터 자동완성 제안(P2).

### 3.5 그래프 뷰 (전체/분야 공용, 6장에서 레이아웃 대안 상세)

**목적**: 계보를 공간적으로 훑어보는 화면. 홈과 분야 페이지에 임베드되는 형태이되, "그래프만 크게 보기" 전체화면 모드(P1)를 추가한다.

**컴포넌트**: 줌/팬 컨테이너, 레인(분야 또는 트랙), 노드(논문 박스), 엣지(부모→자식 화살표), 연도 눈금, **필터 바(P1: 분야 토글, 연도 범위 슬라이더, "미작성 숨기기")**.

**상태**
- 항목 0개: 그래프 영역 자체를 렌더하지 않음(기존 로직 유지 — `if(!items.length) return ''`).
- 노드 강조: 마우스 오버 시 해당 노드의 부모/자식 엣지만 강조하고 나머지를 흐리게(P1, 포커스+컨텍스트 — 6장).

**키보드**: 그래프에 포커스가 있을 때 `+`/`-` 줌, `0` 리셋, 방향키로 인접 노드 이동(부모/자식 방향)(P2).

### 3.6 빌드 산출물 (화면은 아니지만 여러 화면이 공유하는 전제)

`content/graph.json`이 이미 이 역할을 한다 — `tools/build-graph.js`가 150개 파일을 파싱해 만든 정적 JSON(66KB) 하나를 부팅 시 한 번 로드하면, 홈/분야/검색 화면이 150개 파일을 매번 fetch하지 않고도 `stage`·`in`/`out`·`diagram`·`sections`·`bytes`를 쓸 수 있다. "빌드 없음" 원칙과 충돌하지 않는다 — 정적 파일 하나이고, 논문 노트를 고친 뒤 `node tools/build-graph.js`를 한 번 실행하면 갱신된다(README/AUTHORING의 "마무리 검증" 목록에 `node tools/check.js`와 나란히 추가할 것을 권고).

남은 갭 하나: `graph.json`은 파일 mtime을 담지 않아 "최근 갱신" 위젯(3.1)을 만들 수 없다. 필요하면 `build-graph.js`에 `mtime: fs.statSync(file).mtime` 한 줄만 추가하면 되므로, 이 위젯을 P1으로 채택할지 여부는 프론트엔드 구현자가 그 확장 여부와 함께 판단한다.

## 4. 연결 구조의 표현

**전제 — 2.3절의 구분을 화면으로 그대로 옮긴다: 계보(fields.js `parents`)와 언급(graph.json `in`/`out`)은 별개 섹션, 별개 시각 언어를 쓴다.** 실측(2026-09-09)으로 두 관계의 크기 차이가 크다는 게 확인됐다 — transformer는 계보상 자식이 20편인데 언급 백링크(`in`)는 36개, 부모 3편에 언급 아웃링크(`out`)는 18개다. 계보는 항상 작고(대부분 0~3개) 손으로 큐레이션돼 신뢰도가 높지만, 언급은 허브 논문에서 수십 개로 커질 수 있는 부수적 데이터다. 이 차이를 UI가 숨기면 "왜 이 논문은 계보 화살표가 3개뿐인데 다른 곳엔 36개나 있지"라는 혼란이 생긴다 — 그래서 아예 다른 이름, 다른 자리, 다른 모양을 쓴다.

### 4.1 계보 — "이 논문이 딛고 선 것 / 이 논문 위에 선 것" (기존 유지)
- 정의: `fields.js`의 `parents`(내려오는 방향은 `W.childrenOf`로 역산). 저자가 의도적으로 고른 직접 영향 관계.
- 표시: 기존 pill 그대로. **추가**: 부모가 다른 분야 소속이면 pill에 그 분야 색 점을 찍는다(예: DETR 페이지에서 부모 transformer는 llm 색) — 교차분야 서사를 시각화(2.2절 "교차분야 링크").
- 이 관계만 전체/분야 계보도의 화살표로 그린다. **언급 관계는 계보도에 절대 섞지 않는다** — 섞으면 지금의 연도×레인 레이아웃이 감당 못 할 밀도가 된다(6장의 A/B 대안이 전제하는 게 바로 이 "계보만 그린다"는 제약이다).

### 4.2 언급 — "본문에서 언급함 / 본문에서 언급됨" (신규, graph.json)
- 정의: 현재 논문의 `out`(이 논문 본문이 링크를 건 문서들) / `in`(이 논문을 링크로 건 다른 문서들 — `out`의 역인덱스, 진짜 Obsidian식 백링크).
- 표시 규칙: 개수가 5개 이하면 전부 펼침, **5개 초과면 상위 5개(알파벳순 또는 slug순, 정렬 기준은 결정론적이면 됨) + "+N개 더 보기"** 로 접는다. "더 보기"는 아코디언 펼침(모달 아님 — 페이지 이탈 없이).
- 시각 언어: pill이 아니라 **플레인 텍스트 링크를 콤마로 나열** + 옆에 개수 배지(`언급됨 (36)`). 계보 pill과 확실히 다르게 보이도록 — 색상·모양은 비주얼 디자이너 몫이지만, "이건 계보가 아니다"가 형태만으로 구분돼야 한다는 게 이 스펙의 요구사항.
- 씨앗 논문에도 표시된다(3.3절 씨앗 페이지 와이어프레임 참조) — 언급 데이터는 상대방 노트의 본문에서 나온 것이라 이 논문 자체가 씨앗이어도 `in`은 값을 가질 수 있다(cyclegan 예시).
- 배치: 논문 페이지 섹션 10번, "계보"(9번) 바로 다음. 계보 섹션과 시각적으로 구분되는 카드/구획으로 분리한다(같은 박스 안에 이어 쓰지 않는다).

### 4.3 로컬 그래프 (1~2홉, 신규) — 계보 우선, 언급은 보조
- **기본 범위(1홉, 계보만)**: 부모(1홉) + 현재 + 자식(1홉) — `parents`/`children` 기반. 대부분의 논문은 부모 1~3 + 자식 0~20이라 이 정도가 안정적으로 읽힌다.
- **2홉 확장**: 부모의 부모 + 자식의 자식까지. 계보 기준 노드 수가 20개를 넘으면(허브 논문) 2홉을 생략하고 1홉만 표시 + "전체 계보도에서 보기" 링크로 대체.
- **언급 오버레이(옵션, 토글로 켬)**: 로컬 그래프 위에 `in`/`out` 중 **계보에 없는 것만** 가는 점선으로 추가 표시(중복 방지: 이미 계보 화살표로 그려진 쌍은 점선을 겹치지 않는다). 허브 논문(transformer급, `in`+`out`이 20 넘는 경우)은 이 오버레이를 기본 꺼짐으로 하고, 대신 "언급 36개, 펼쳐서 보기" 텍스트 버튼만 노출 — 그래프에 점선 36개를 다 그리면 로컬 그래프의 목적(빠른 파악)을 해친다.
- 형제(같은 부모를 공유하는 다른 자식)는 로컬 그래프에 포함하지 않는다(4.4의 "함께 읽으면 좋은"으로 별도 노출).
- 레이아웃: 전체 계보도와 같은 연도×레인 방식을 쓰지 않는다 — 노드 수가 적으므로 **방사형(현재 노드 중앙, 부모는 위, 자식은 아래)**. 상세는 6장.
- 배치: 논문 페이지 "계보" 섹션(9번) 안에, pill 목록 아래.

### 4.4 "함께 읽으면 좋은" (신규, 100% 파생, 계보 기준)
계산 우선순위(둘 다 걸리면 co-parent가 우선, 최대 4개 노출) — **의도적으로 계보(`parents`)만 쓰고 언급(`in`/`out`)은 쓰지 않는다**: 언급 기반 추천은 허브 논문에서 사실상 무작위 36개 중 고르는 꼴이 되어 신호가 약하다.
1. **공통 부모(co-citation)**: `parents` 교집합이 1개 이상인 다른 논문. 교집합 크기 내림차순.
2. **같은 트랙 형제**: `field`+`track`이 같고 연도가 가장 가까운 논문 2편(앞뒤 각 1편) — 이미 pagenav(‹이전/다음›)가 이 역할을 하므로 **중복 방지**: pagenav에 이미 나온 slug는 "함께 읽으면 좋은"에서 제외.
3. 후보가 0개면 섹션 자체를 숨긴다(빈 위젯 금지).

## 5. 성장 단계 (디지털 가든)

### 5.1 판정 규칙 (`content/graph.json`의 `stage`를 그대로 씀 — 새 기준 만들지 않음)

`tools/build-graph.js`가 이미 4단계를 계산해 `graph.json`에 넣고 있다. UI는 이 값을 그대로 배지로 옮기기만 한다 — 판정 로직을 중복 구현하지 않는다.

| 단계 | 배지 | 조건 (`build-graph.js` 그대로) | 실측(150편) |
|---|---|---|---|
| 🌱 씨앗 (seed) | | `content/papers/<slug>.js` 파일이 없음 | 34 |
| 🌿 새싹 (sprout) | | 파일은 있으나 `full` 조건 미달: `ideas≥3 && legacy≥3 && pitfalls≥2 && diagram && impact && context` 중 하나라도 부족 | 0 (현재는 없음 — 앞으로 작성 중인 파일이 이 단계를 지나갈 수 있음) |
| 🌳 자라는 중 (growing) | | `full` 조건은 만족하지만 `rich`는 아님 | 5 |
| 🌲 상록수 (evergreen) | | `full` **그리고** `rich`: `math≥1 && numbers≥3 && bytes≥6000` 까지 만족 | 111 |

4단계로 고정한다(더 세분화하지 않음). `sprout`가 현재 0편이라고 배지 자체를 빼지 않는다 — 앞으로 작성 중인 파일이 이 단계를 자연스럽게 거쳐간다.

### 5.2 표시 위치
- 분야 페이지 카드 우상단 아이콘.
- 논문 페이지 메타 태그 줄 끝(`[분야][연도][학회]...[🌲 evergreen]`).
- 좌측 내비 트리에서 회색 처리(2.6절, seed만 회색 — sprout/growing은 일반 색으로 이미 "존재하는 콘텐츠"임을 보여준다).
- 검색 결과 리스트: 씨앗은 결과 텍스트를 흐리게 처리하지 않는다 — 씨앗도 유효한 목적지(정리하러 가는 곳)이므로 시각적으로 죽은 링크처럼 보이면 안 됨. 대신 배지만 붙인다.
- 2.4절 "핵심 논문 랭킹"·"다음에 쓸 논문 큐"에서 `stage`와 `in.length`를 조합해 노출.

### 5.3 미작성 문서를 열었을 때 (씨앗 페이지) — 상세는 3.3절 와이어프레임 참조
핵심 원칙 3가지:
1. **빈 화면 금지** — 계보(부모/자식, `fields.js`)와 언급(`graph.json`의 `in`, 4.2절)과 브레드크럼은 노트 파일 없이도 이미 계산돼 있으므로 항상 보여준다. seed 논문도 `in`이 비어 있지 않을 수 있다(cyclegan처럼 4곳에서 언급됨) — 이 경우 "생각보다 중요한 논문인데 아직 안 썼다"는 신호를 그대로 드러낸다.
2. **다음 행동을 지시** — "content/papers/<slug>.js 를 만드세요" + AUTHORING.md 링크 + transformer.js 예시 링크. 파일 경로는 slug를 실제 값으로 채워 보여준다(복붙 가능하게).
3. **막다른 골목 아님** — 이전/다음 논문 내비(pagenav)는 씨앗 페이지에도 동일하게 붙는다. 씨앗이라고 탐색이 끊기면 안 된다.

## 6. 그래프 가독성

### 그래프 우선순위 (확정)
세 그래프 화면의 구현 순서는 **① 논문 페이지 로컬 그래프(4.3) → ② 분야 페이지 계보도 → ③ 홈의 전체 150편 지도** 순이다. 이유: S1·S2(1장)에서 실제로 가장 자주 열리는 그래프는 "지금 보는 논문 주변"(로컬)과 "지금 보는 분야 하나"(분야 계보도)이고, "150편 전체를 한 화면에" 조망하는 순간은 상대적으로 드물다. 그래서:
- **홈의 전체 그래프는 주 화면이 아니라 보조 뷰(secondary view)로 재정의한다.** 없어도 사이트가 기능하지만(홈 카드 그리드가 이미 개관을 제공), 있으면 좋은 조감도다.
- 보조 뷰로 격하되는 대신, **줌/팬과 분야 필터(아래 대안 A·B)는 "나중에 붙이는 개선"이 아니라 이 화면을 P0로 출시하기 위한 필수 전제**로 승격한다 — 필터·줌 없이 150편을 통짜로 렌더링한 현재 상태로는 아예 출시하지 않는 편이 낫다(가로 스크롤 지옥이 첫인상이 되는 것보다 낫다).
- 로컬 그래프(①)와 분야 계보도(②)는 상대적으로 노드 수가 적어(로컬 20개 이하, 분야 최대 33편) 새 레이아웃 없이도 읽히므로, 그래프 관련 P0 작업의 우선 착수 대상이다.

### 문제 정의
현재 `js/wiki/graph.js`는 연도를 가로축, 분야/트랙을 세로 레인으로 고정 배치한다. 150편(홈)이면 연도 폭(`years.length × 142px`)만으로 가로 4,000px 안팎이 되고, 레인마다 겹침 회피(`while(rows[r]!==undefined...)`)로 세로도 늘어난다. 스크롤이 두 방향으로 다 생기며 "전체를 한눈에"가 실패한다. 분야 페이지(최대 33편, vision)는 같은 함수를 쓰지만 항목 수가 훨씬 적어 이 문제가 심각하지 않다 — 아래 대안들은 주로 **홈의 전체 그래프**를 겨냥한다.

### 대안 A — 줌/팬 + 미니맵 (최소 변경)
레이아웃 로직은 그대로 두고 SVG를 `viewBox` 기반 줌/팬 컨테이너에 넣는다(마우스 휠 줌, 드래그 팬, 우하단 미니맵으로 현재 뷰포트 표시). 구현 비용이 가장 낮다.
- 장점: `graph.js`의 좌표 계산을 하나도 안 건드림. 즉시 적용 가능.
- 단점: "한눈에 전체 구조"는 여전히 안 됨 — 축소하면 글자가 안 보이는 전형적인 문제. 근본 해결이 아니라 완화.

### 대안 B — 필터 + 접힘 (분야별 레인 토글)
홈의 전체 그래프에 분야 체크박스를 달아 원하는 분야만 레인으로 렌더링. 접힌 분야는 "N편, 펼치기" 한 줄로 축약. 트랙 레벨도 같은 방식.
- 장점: 실제로 보고 싶은 부분만 남기므로 가로/세로 폭이 필요한 만큼만 늘어남. 구현 비용 중간(레인 목록을 필터링해서 기존 `W.graph()`에 넘기면 됨 — 함수 시그니처 변경 없이 `lanes` 배열만 줄이면 된다).
- 단점: 기본 상태에서 "전체가 몇 편인지" 조망은 못 함(단, 홈 카드 그리드가 이미 그 역할을 하므로 손실이 크지 않음).

### 대안 C — 포커스+컨텍스트 (허브 중심 방사형, 로컬 그래프와 통합)
전체 계보도는 **연도×레인을 버리고**, 중요도(2.2절의 자식 수 = 허브 점수, 또는 graph.json의 `in.length`) 상위 논문만 큰 노드로, 나머지는 작은 점으로 방사형/힘-지향(force-directed) 배치. 클릭 시 그 노드를 중심으로 4.3절의 로컬 그래프 방사형 뷰가 열린다.
- 장점: 가장 "그래프답게" 읽힘. 전체 개관(허브 위주)과 상세 탐색(로컬 그래프)이 하나의 상호작용 언어로 통일됨.
- 단점: 구현 비용이 가장 크다(force-directed 레이아웃은 좌표를 매번 재계산해야 하고, 빌드 없는 바닐라 JS 환경에서 라이브러리 없이 직접 짜야 함 — 프로젝트 제약상 외부 JS 라이브러리 사용 여부 확인 필요, `README.md`는 "빌드 없음"만 명시하고 CDN 스크립트 금지는 명시하지 않음).

### 권고: **A를 P0, B를 P1으로 함께 채택. C는 P2(로컬 그래프에 한해서만).**
이유: 이 사이트의 실제 열람 패턴(S1·S2)은 "전체 150편을 한 화면에 조망"이 아니라 "관심 분야/트랙 하나를 깊게 본다"이다. 분야 페이지의 그래프는 이미 한 분야(최대 33편, vision)로 좁혀져 있어 A만으로도 충분히 읽힌다. 문제가 진짜 심각한 건 **홈의 전체 그래프(150편)** 뿐이므로, 거기에만 B의 분야 필터를 얹으면 비용 대비 효과가 가장 크다. C(force-directed)는 4.3절 로컬 그래프(노드 20개 이하로 상한을 이미 정해둠)에는 잘 맞지만, 150편 전체에 쓰기엔 구현 비용과 "예측 가능한 위치"를 잃는 단점이 크다 — 개발자 위키는 "어제 봤던 그 논문이 항상 같은 자리에 있다"는 안정성도 가치이므로, 전체 그래프의 결정론적 레이아웃(연도×레인)은 유지할 가치가 있다.

**필터 바 스펙(대안 B, P1)**: 홈 그래프 상단에 분야 칩 10개(전체 선택이 기본), 클릭으로 토글. 0개 선택 시 "최소 1개는 선택하세요"로 막고 이전 선택 유지(그래프가 완전히 비는 상태 금지). 선택 상태는 `localStorage`에 저장해 다음 방문 시 유지(P2).

## 7. 우선순위

`content/graph.json`이 이미 존재하므로, 예전에 "구현 비용이 커서 P2"였던 언급/백링크·성장단계 항목들이 대부분 P0/P1로 앞당겨졌다. 그래프 관련 항목은 6장의 확정 순서(로컬 → 분야 → 홈)를 따른다.

### P0 (반드시)
1. **`graph.json` 로드 배선** — 부팅 시 1회 fetch, `stage`/`in`/`out`/`diagram` 등을 앱 전역에서 쓸 수 있게 함. 아래 항목 전부의 전제.
2. 씨앗 페이지 개선 — 계보(4.1)·언급(4.2)·브레드크럼·pagenav를 항상 표시, "다음 행동" 안내 문구 (3.3, 5.3)
3. 성장 단계 배지 4종(🌱🌿🌳🌲, `graph.json`의 `stage` 그대로 사용), 분야 카드·논문 메타에 노출 (5.1, 5.2)
4. **언급/백링크 섹션** — "본문에서 언급함·언급됨", 계보 pill과 시각적으로 분리, 5개 초과 시 접힘 (4.2)
5. **로컬 그래프(1홉, 계보 기준)** — 논문 페이지, 그래프 우선순위 1위 (4.3, 6장)
6. **분야 계보도 가독성** — 대안 A(줌/팬), 그래프 우선순위 2위 (6장)
7. 논문 페이지 헤더 즉시 렌더 + 본문만 스켈레톤 (3.3 로딩 상태)
8. "함께 읽으면 좋은" 섹션 (co-parent 기준만, 계보 데이터로만 계산, 형제 폴백 포함) (4.4)
9. **홈 전체 그래프 — 줌/팬 + 분야 필터를 갖춘 채로만 출시** (그래프 우선순위 3위, 보조 뷰. 6장 — 대안 A+B 없이 배포하지 않는다)

### P1 (넣으면 좋음)
10. 좌측 고정 내비 트리, seed 논문·전체 seed 분야 회색 처리 (2.6)
11. 검색 필터 문법 — `field:`,`year:`,`stage:`,`diagram:`,`cites:`,`mentions:` (3.4)
12. 2.4절 질의 뷰 1~5번 구현 (다음에 쓸 논문 큐 / 핵심 논문 랭킹 / 분야 완성도 대시보드 / 다이어그램 감사 / 최근 흐름) — 전부 필터 조합, 새 화면 불필요 (2.4)
13. 로컬 그래프 2홉 확장 + 언급 오버레이 토글 (4.3)
14. 홈 위젯 3종 — 이어보기 / 최근 갱신(`build-graph.js`에 `mtime` 추가 필요) / 오늘의 씨앗(큐 기반) (3.1, 3.6)
15. 링크 복사 버튼, 로컬 그래프 hover 프리뷰(Obsidian식) (S4, 컨셉 0장)
16. `build-graph.js`에 `mtime` 필드 추가 — 14번의 전제 (3.6)

### P2 (나중)
17. `method_tags` 등 자유 태그 확장 속성 — 2.4절 질의 뷰로 부족해질 때 재검토 (2.5)
18. `read_status`/`localStorage` 개인화 (2.5)
19. 그래프 뷰 전체화면 모드, 노드 hover 시 엣지 강조 (3.5)
20. force-directed 방사형 전체 그래프 (대안 C) — 로컬 그래프(4.3)에서 먼저 검증 후 확대 여부 재검토

23. 2.4절 질의 뷰 6번(숨은 연결 찾기 — `parents`와 `out`의 교차 비교, 계산 비용 있음) (2.4)
