# 그래프 인터랙션 스펙 — 클릭은 선택, 이동은 별도

작성자: UX/IA 디자이너 · 대상: 프론트엔드 구현자, 비주얼 디자이너
범위: `js/wiki/graph.js`가 그리는 두 그래프(`W.graph` = 전체/분야 계보도, `W.localGraph` = 논문 페이지 로컬 그래프)의 노드 클릭 인터랙션만 다룬다. `UX-SPEC.md` 4장(연결 구조의 표현)·6장(그래프 가독성)을 전제로 하고, 거기서 정한 계보/언급 구분·1~2홉 범위·레이아웃은 바꾸지 않는다.

배경: 위키 주인의 문제 제기 — 지금은 노드를 누르면 곧장 `#/p/<slug>`로 이동해, 계보 구조를 살펴보려는 시도 자체가 매번 페이지 이탈로 끝난다. **클릭은 선택(관계 강조)으로, 이동은 별도 동작으로 분리한다.**

---

## 1. 선택 상태의 정의

**선택은 노드 하나에 대한 단일 상태다.** 동시에 두 개를 선택할 수 없다 — 다른 노드를 클릭하면 이전 선택은 해제되고 새 노드가 선택된다(멀티 선택 없음, 이 그래프의 목적은 "이 논문이 무엇과 연결됐는지" 하나씩 확인하는 것이지 집합 비교가 아니다).

선택된 노드를 기준으로 강조되는 대상:

| 관계 | 범위 | 표시 대상 |
|---|---|---|
| 부모(선택 노드가 딛고 선 것) | 1홉만 | 부모 노드 테두리 + 부모→선택 화살표 |
| 자식(선택 노드 위에 선 것) | 1홉만 | 자식 노드 테두리 + 선택→자식 화살표 |
| 그 외 모든 노드·화살표 | — | dim(흐리게) 처리 |

**방향은 다르게 표시한다.** 부모와 자식을 같은 색으로 뭉뚱그리면 "화살표가 들어오는 관계인지 나가는 관계인지"가 다시 안 보여, 애초에 이 기능을 만드는 이유(연결 이해)가 무색해진다. 부모 강조와 자식 강조는 서로 다른 시각 언어를 쓴다(구체 색상은 4장 참조).

**1홉만 강조하고 2홉은 강조하지 않는다.** 이유:
- 전체/분야 계보도는 이미 화면에 다홉 구조가 다 그려져 있다 — 선택 시 2홉까지 밝히면 transformer급 허브에서 밝는 노드가 수십 개가 되어 "무엇과 직접 연결됐는지"라는 원래 목적이 다시 흐려진다.
- 로컬 그래프는 UX-SPEC 4.3에서 이미 중심 논문 기준 1~2홉을 **레이아웃 자체**로 펼쳐 보여준다. 그 위에서 굳이 선택으로 또 다른 홉수를 강조할 필요가 없다 — 로컬 그래프에서 선택은 "레이아웃엔 이미 다 보이는데, 그중 어느 화살표가 정확히 이 노드에 연결된 것인지" 한 겹 더 명확히 짚어주는 역할이면 충분하다.
- 2홉을 보고 싶으면 그 노드로 이동해서(3장의 이동 수단으로) 그 노드를 중심으로 다시 보면 된다 — 그게 로컬 그래프가 원래 하는 일이다.

**dim은 켠다.** 선택 안 된 노드·화살표를 흐리게 하지 않으면 강조가 배경 밀도에 묻힌다(특히 홈 전체 그래프 150편). 단, dim은 "존재감을 지우는" 수준이 아니라 "덜 중요해 보이게" 하는 수준으로 — dim 상태에서도 텍스트는 읽혀야 한다(완전 투명 금지, 클릭 대상에서 제외하지도 않음 — dim된 노드도 여전히 클릭하면 선택이 그쪽으로 옮겨간다).

## 2. 계보와 언급의 구분 — 선택 시 기본은 계보만

선택 강조는 **계보 화살표만** 대상으로 한다. 언급(`in`/`out`)은 기본적으로 강조에 섞이지 않는다.

이유는 UX-SPEC 4장에서 이미 확정한 원칙의 연장이다 — "언급 관계는 계보도에 절대 섞지 않는다"(4.1절). 전체/분야 계보도(`W.graph`)는 애초에 계보만 그리므로 여기서 선택은 자연히 계보만 강조한다. 로컬 그래프(`W.localGraph`)는 UX-SPEC 4.3에서 언급 오버레이를 "옵션, 토글로 켬"으로 정해뒀는데, 그 토글이 꺼진 기본 상태에서는 언급 화살표 자체가 화면에 없으므로 선택도 계보만 강조하는 게 당연하다. **토글을 켜서 언급 오버레이(점선)가 화면에 나와 있는 동안에는, 선택 시 그 점선 중 선택 노드에 닿는 것도 함께 강조한다** — 이미 화면에 그려둔 정보를 선택이 무시하면 오히려 어색하다. 단 이때도 부모/자식 화살표와는 다른(옅은) 강조 톤을 써서 "이건 계보가 아니라 언급이다"가 강조 상태에서도 유지되게 한다.

## 3. 이동 수단 — 정보 카드의 "이동하기" 버튼

노드를 선택하면 그래프 옆(또는 아래)에 **작은 정보 카드**가 뜬다. 카드에는 논문명·연도·성장 단계 배지·부모/자식 개수 요약이 있고, 맨 아래에 **"이 논문으로 이동 →"** 버튼이 있다. 이동은 이 버튼을 눌러야만 일어난다.

더블클릭·Enter 키·노드 안 화살표 아이콘 같은 대안도 검토했으나 채택하지 않는다. 이유:
- **더블클릭**은 SVG `<g>` 노드처럼 촘촘히 배치된 대상에서 오검출이 잦다(연타가 다른 노드로 새는 경우, 트랙패드에서 더블클릭 판정이 불안정한 경우) — "실수로 이탈하지 않게"라는 요구를 오히려 어긴다.
- **Enter 키**는 키보드 사용자에게는 자연스럽지만, 이 그래프의 주 사용자는 마우스로 노드를 훑어보는 사람이고 Enter 단독으로는 마우스 사용자에게 이동 수단이 없다 — 결국 버튼이 따로 필요해지므로 별도 규칙을 하나 더 얹을 이유가 없다. (키보드 Enter는 그대로 살리되, "선택"과 "이동"의 키를 분리한다 — 6장 참조. 버튼과 Enter가 같은 목적지로 수렴하는 것은 무방하다.)
- **노드 안 화살표 아이콘**은 노드가 이미 126×40px(전체 계보도) / 132×40px(로컬 그래프)로 작아 아이콘을 얹으면 텍스트와 겹치거나 타겟이 더 작아진다. transformer처럼 자식 20편이 몰린 화면에서는 아이콘 오클릭이 텍스트 클릭보다 더 잦아질 것이다.

정보 카드 버튼은 반대로 **선택이라는 명시적 중간 단계를 거친 뒤에만 나타나는 목표물**이라 오클릭 위험이 낮고(카드 자체가 노드보다 크고 그래프와 떨어진 자리에 뜬다), 동시에 "누르면 바로 간다"는 답답함도 없다(선택 한 번, 버튼 한 번 — 최대 2클릭으로 항상 도달 가능하다).

## 4. 선택 해제

| 동작 | 결과 |
|---|---|
| 그래프 배경(빈 공간) 클릭 | 선택 해제, 카드 닫힘 |
| Esc 키 | 선택 해제, 카드 닫힘. 포커스는 방금 선택했던 노드에 남는다(포커스 이동 없음) |
| 이미 선택된 노드를 다시 클릭 | 선택 해제(토글) — 같은 노드를 두 번 눌러 끄는 것도 허용 |
| 다른 노드 클릭 | 이전 선택 해제 + 새 노드 선택(4장 표 참조, 해제 애니메이션 없이 즉시 전환) |
| 정보 카드 안의 닫기(×) | 선택 해제, 카드 닫힘 |

## 5. 호버와의 관계 — 역할을 나눈다

호버와 선택은 서로 다른 목적을 가지므로 같은 화면 요소를 두고 경쟁하지 않게 분리한다:

- **호버 = 프리뷰(문서 요약 팝오버)**. UX-SPEC 0장에서 이미 "링크 호버 프리뷰(신설)"로 정한 기능이 노드에도 그대로 적용된다 — 노드 위에 마우스를 올리면 짧은 지연(예: 200ms 정도 — 정확한 값은 인터랙션 튜닝 몫) 후 논문 요약 팝오버가 뜬다. 이건 선택과 무관하게 항상 동작한다.
- **선택 = 관계 강조**. 호버는 관계를 강조하지 않는다 — 호버할 때마다 화살표 색이 바뀌면 마우스가 그래프 위를 지나가는 것만으로 그림이 계속 깜빡여 오히려 산만해진다. "무엇과 연결됐는지"는 클릭(의도적 행동)으로만 확정한다.
- 충돌 지점은 "선택된 노드에 마우스를 올렸을 때"인데, 이때도 프리뷰 팝오버는 정상 동작한다 — 선택 강조(테두리·화살표 색)와 프리뷰 팝오버(텍스트 요약)는 서로 다른 레이어라 겹쳐도 문제없다.

## 6. 키보드 접근성

노드의 역할이 "링크"에서 "선택 가능한 항목"으로 바뀌므로 `role="link"`는 더 이상 맞지 않는다. `role="button"`으로 바꾸고 `aria-pressed`로 선택 상태를 알린다.

| 요소 | 속성 |
|---|---|
| 각 노드 `<g>` | `role="button"` `tabindex="0"` `aria-pressed="true\|false"` `aria-label="<논문명> (<연도>), 선택하면 연결된 논문이 강조됩니다"` |
| 정보 카드의 이동 버튼 | 일반 `<button>`, 카드가 열리면 자동 포커스하지 않는다(스크린리더 사용자가 갑자기 포커스가 튀는 것을 막기 위해 — 카드가 열렸다는 것 자체는 `aria-live="polite"` 영역으로 알린다) |

동작 정의:

| 키 | 상황 | 결과 |
|---|---|---|
| Tab / Shift+Tab | 어디서든 | 노드 사이를 DOM 순서로 이동(전체 계보도는 레인→연도순, 로컬 그래프는 부모행→중심→자식행 순 — 현재 DOM 렌더 순서 그대로 사용, 별도 순서 재정의 안 함) |
| 방향키(←→↑↓) | 노드에 포커스 있을 때 | 정의하지 않는다 — 도입하지 않는다. 노드 배치가 격자가 아니라("한 줄에 너무 많으면 접어서 여러 줄로" 폴딩 로직 때문에) 방향키의 "다음 노드"가 시각적으로 예측 가능하지 않다. Tab만으로 충분하다. |
| Enter / Space | 노드에 포커스 있을 때 | 그 노드를 선택(4장 표의 "다른 노드 클릭"과 동일 취급) — **이동하지 않는다.** 클릭과 동작을 통일해 "선택"의 의미를 키보드·마우스 양쪽에서 일관되게 유지한다 |
| Enter | 정보 카드의 이동 버튼에 포커스 있을 때 | 이동(버튼이므로 표준 동작 그대로) |
| Esc | 어디서든(그래프 내부에 포커스) | 4장과 동일 — 선택 해제, 포커스 유지 |

## 7. 터치 환경

호버가 없으므로 "프리뷰 팝오버"는 터치에서 발생하지 않는다 — 손가락 탭이 곧 클릭이다. 규칙은 마우스와 동일하게 유지한다: **첫 탭 = 선택**(카드가 뜬다), **카드 안 "이동하기" 버튼 탭 = 이동**. 더블탭 이동 같은 별도 제스처는 추가하지 않는다 — 3장에서 더블클릭을 배제한 이유(오검출)가 터치에서는 한층 더 크다(손가락은 마우스보다 판정 오차가 크다).

빈 공간 탭으로 선택 해제하는 동작은 그대로 유지한다(4장). 터치에는 Esc가 없으므로 이것이 유일한 해제 수단이 된다 — 카드의 닫기(×) 버튼도 항상 노출해 대체 수단을 준다.

## 8. 두 그래프의 차이

전체/분야 계보도(`W.graph`)와 로컬 그래프(`W.localGraph`)는 **선택·강조·이동의 규칙 자체는 동일하게 따른다**(1~7장 전부 공통). 다만 다음 두 가지는 그래프의 구조상 자연히 달라진다:

- **로컬 그래프의 중심 노드(`node-center`)는 선택 대상에서 제외한다.** 이미 "지금 보고 있는 논문"이라 선택할 이유가 없다 — 클릭해도 아무 일도 일어나지 않는다(현재 `isCenter` 노드가 `data-slug`도 `cursor:pointer`도 없는 것과 동일하게, `role="button"`·`tabindex`도 부여하지 않는다).
- **로컬 그래프에서 노드를 선택하면 정보 카드에 "전체 계보도에서 보기" 링크는 넣지 않는다** — 로컬 그래프는 이미 그 논문 주변만 보여주는 목적을 가진 화면이라, 정보 카드는 이동 버튼 하나로 충분히 단순하게 유지한다. 이 링크는 UX-SPEC 4.3의 "truncated=true일 때(20개 초과 허브)" 로컬 그래프 자체에 이미 노출되므로 중복이다.

두 그래프에 공통 규칙을 쓰는 이유: 사용자가 홈→분야→논문 페이지로 옮겨 다니며 같은 그래프 컴포넌트를 반복해서 보는데, 화면마다 클릭 의미가 바뀌면 매번 다시 학습해야 한다. "클릭하면 선택되고, 카드의 버튼으로 이동한다"는 하나의 규칙만 외우면 세 화면(홈·분야·논문) 어디서나 통한다.

## 9. 선택 상태의 지속성

**선택은 URL에 반영하지 않는다.** 페이지를 옮기면(다른 해시로 라우팅) 선택은 사라진다 — 그래프를 다시 그릴 때(`route()`가 `viewPaper`/`viewField`를 다시 호출할 때) 선택 상태는 초기화된 새 DOM에서 자연히 없어지므로 별도 정리 로직도 필요 없다.

**같은 화면 안에서 필터를 바꾸면(6장 B안 P1, 분야 칩 토글) 선택은 해제한다.** 선택된 노드가 필터로 화면에서 사라지는 경우 강조 대상이 없는데 카드만 남는 상태를 방지하기 위해서다 — 필터 변경은 항상 선택 초기화를 동반한다.

지속성을 주지 않는 이유: 이 선택은 "지금 이 화면을 보면서 잠깐 관계를 확인하는" 용도이지, 북마크하거나 공유할 대상이 아니다(공유는 UX-SPEC S4가 이미 논문 페이지 링크로 담당한다). URL 파라미터를 추가하면 라우팅 로직(`app.js`의 `route()`)에 상태를 하나 더 얹어야 하는데, 그 비용에 비해 "새로고침해도 강조가 남아 있으면 좋겠다"는 수요는 낮다.

## 시각 규칙

작성: 비주얼 디자이너. 토큰은 `css/tokens.css`에 이미 추가했다(`--graph-sel-*`,
`--graph-dim-*`, `--graph-card-*`) — 이 절은 그 토큰을 "어디에 어떻게" 쓰는지
규정한다. `DESIGN-SYSTEM.md` §7(계보 그래프 스타일)·§5.1(성장 단계)·§5.3(허브
크기)과 충돌하지 않는지 매 항목에서 확인했다.

### 시-1. 왜 새 색 두 개가 필요한가 — 색상환이 이미 꽉 찼다

`DESIGN-SYSTEM.md`가 이미 분야 10색 + 상태 4색 + 성장단계 4색 + accent 1색으로
색상환을 거의 다 썼다(`--field-*`, `--state-*`, `--stage-*`, `--accent`). 이번
선택 강조는 그 위에 얹는 **다섯 번째 상태 묶음**이라, 새 색을 쓰려면 반드시
기존 14개 톤과 헷갈리지 않는 자리를 찾아야 했다.

그래서 부모/자식 방향색은 **채도를 크게 낮춘** 난색·한색 한 쌍으로 잡았다 —
`--graph-sel-parent`(모래/세피아, 라이트 `#8a6a3f` · 다크 `#d8b989`), `--graph-sel-child`
(슬레이트 블루, 라이트 `#3f6a8a` · 다크 `#89b4d8`). 분야색·상태색은 전부
"눈에 띄어야 하는" 채도로 고른 색이고(§2.4~2.6), 이 두 색은 일부러 그 반대로
탁하게 눌러서 "이건 분류(카테고리)가 아니라 지금 이 순간의 관계 방향"이라는
게 채도 차이만으로 구분되게 했다. 가장 가까운 이웃은 `nlp` 분야색(`#96690a`)
인데, `--graph-sel-parent`(`#8a6a3f`)는 그보다 명도·채도를 낮춰 나란히 놓아도
"저건 NLP 논문이구나"로 오독되지 않는다 — 실제로 두 색은 항상 다른 위치에
쓰인다(레인 레이블 텍스트 vs 노드 테두리)는 점도 오독 위험을 낮춘다.

**대비 실측** (자기 표면 기준, WCAG 1.4.11 UI 컴포넌트 최소 3:1 대비):

| 토큰 | 라이트 값 | `--surface`(#fff) 대비 | `--bg-page`(#f4f5f8) 대비 | 다크 값 | `--surface`(#12161f) 대비 | `--bg-page`(#0a0d13) 대비 |
|---|---|---|---|---|---|---|
| `--graph-sel-parent` | `#8a6a3f` | **4.98 : 1** | **4.57 : 1** | `#d8b989` | **9.67 : 1** | **10.39 : 1** |
| `--graph-sel-child` | `#3f6a8a` | **5.77 : 1** | **5.29 : 1** | `#89b4d8` | **8.26 : 1** | **8.88 : 1** |

(상대휘도 공식으로 직접 계산 — `--accent`가 라이트에서 5.00:1을 확보한 것과
같은 방식·같은 자릿수로 맞췄다.) 두 색 다 최소 기준의 1.5배 이상 여유가
있어 엣지(1.3~2.1px 얇은 선)와 노드 테두리(1.8px) 모두에서 확대 없이
식별된다. 부모/자식 색은 서로 명도差(라이트 L≈0.161 vs 0.132, 다크
L≈0.511 vs 0.429)와 색상差(황갈 vs 청람)를 동시에 가져서, 대부분의
색각이상 유형에서도 밝기 차이만으로 구분 가능하다(적-록만으로 구분되는
쌍이 아니다).

### 시-2. 7개 상태의 시각 위계 — 채널 배분표

한 화면에 최대 7개 상태가 동시에 존재한다(선택 노드 / 부모 이웃 / 자식 이웃 /
무관 노드 / 부모 방향 엣지 / 자식 방향 엣지 / 무관 엣지). 분야색(레인)과
성장단계(테두리 스타일)는 이미 "레인 배경·레이블"과 "테두리 점선/굵기" 채널을
쓰고 있으므로, 선택 강조는 **테두리 색 + 테두리 굵기 + 배경 fill(선택 노드
1개 예외) + 불투명도** 네 채널을 조합해 겹치지 않게 배분한다.

| 상태 | 테두리 색 | 테두리 굵기 | 배경 fill | 그룹 불투명도 |
|---|---|---|---|---|
| 선택된 노드(중심) | `--graph-sel-node-border`(=accent) | `--graph-sel-node-border-w` 2.5px | `--graph-sel-node-fill`(accent 14% tint) | 1.0 |
| 부모 이웃 노드 | `--graph-sel-parent` | `--graph-sel-neighbor-border-w` 1.8px | 없음(`--graph-node-fill` 그대로) | 1.0 |
| 자식 이웃 노드 | `--graph-sel-child` | 1.8px | 없음 | 1.0 |
| 무관 노드 | 기존 `--graph-node-border` 그대로 | 기존 그대로(1px, 성장단계별 §5.1 규칙 유지) | 없음 | **`--graph-dim-opacity` 0.32** |
| 부모→선택 엣지 | `--graph-sel-parent` | `--graph-sel-edge-w`(2.1px, 기존 hi 굵기 재사용) | — | 1.0 |
| 선택→자식 엣지 | `--graph-sel-child` | 2.1px | — | 1.0 |
| 무관 엣지 | 기존 `--graph-edge`/`--edge-backlink` 색 그대로 | 기존 그대로 | — | **`--graph-dim-edge-opacity` 0.16** |

세부 규칙:
- **배경 fill을 쓰는 건 선택된 노드 1개뿐이다.** 부모/자식 이웃까지 fill을
  칠하면 "이웃 = 선택됨"으로 오인되고, §7의 "호버해도 배경은 안 바뀐다"
  원칙과도 어긋난다. 이웃은 테두리 색만으로 표시한다.
- **불투명도 채널은 무관 상태 전용이다.** 선택·이웃 노드/엣지는 항상
  불투명도 1.0 — "진하게 만든다"가 아니라 "무관한 것만 흐리게 만든다"는
  단방향 규칙으로 통일해, 진하기 다른 3~4단계를 섞어 위계를 흐리지 않는다.
- **성장 단계 표시(점선=seed)는 선택 상태와 독립적으로 유지된다.** 부모
  이웃이 우연히 seed 단계 논문이면, 테두리는 `--graph-sel-parent` 색 +
  여전히 점선(`stroke-dasharray:3 3`)이다 — 색(선택)과 패턴(성장단계)이
  서로 다른 채널이라 동시에 표시해도 신호가 죽지 않는다. 굵기만 예외:
  이웃 상태의 1.8px가 seed/sprout/growing 굵기(1~1.6px)보다 항상 굵어
  "선택으로 인한 강조"가 "성장 단계로 인한 강조"를 시각적으로 덮는다 —
  의도한 것이다(지금 이 순간엔 관계가 성장 단계보다 우선 정보).
- **허브 노드(§5.3, 피인용 상위 2px 테두리)가 이웃으로 강조되는 경우**도
  마찬가지로 색만 `--graph-sel-parent`/`-child`로 바뀌고 굵기는 이웃 규칙
  1.8px를 따른다(허브의 2px보다 살짝 얇아지지만, 허브 표시는 "이 논문이
  전체적으로 중요하다"는 정적 정보이고 선택 강조는 "지금 이 관계"라는
  동적 정보라 후자가 시각적으로 앞서는 게 맞다).

### 시-3. dim 처리 — 구체 수치와 근거

- **노드: 불투명도 0.32.** SVG `<g class="node">` 그룹 전체(테두리+텍스트+
  fill)에 건다 — 개별 속성을 따로 흐리면 안티앨리어싱 경계에서 색이
  번져 보인다. 0.32는 임의값이 아니라 "`--text-faint`가 주는 인상"을
  기준 삼았다 — `DESIGN-SYSTEM.md` §2.2가 이미 `--text-faint`(대비
  3.19:1~3.67:1, "장식적" 등급)를 "본문에서 밀려난 정보"의 하한으로 써왔다.
  dim된 노드도 같은 인상(존재는 알지만 지금 읽을 대상은 아님)을 줘야
  하므로, `--text-primary`(라이트 대비 16.21:1) 텍스트에 0.32를 곱하면
  실효 대비가 대략 3~4:1대로 떨어져 `--text-faint`와 비슷한 급으로
  내려온다 — 계산 없이 "적당히 흐리게"로 고르지 않았다는 뜻이다.
- **엣지: 불투명도 0.16, 노드보다 낮다.** 홈 전체 그래프(150편)는 엣지 수가
  노드 수보다 훨씬 많고 선이 가늘어(1~1.3px) 겹치면 뭉친 회색 덩어리로
  보인다. 노드와 같은 0.32를 쓰면 무관 엣지 수백 개가 겹쳐 보이는 밀도
  자체가 시각적 잡음을 만든다 — 그래서 엣지만 한 단계 더 낮춰 "배경
  지형(지금 이 분야에 얼마나 많은 논문이 오가는지)"은 흐릿하게 남기되
  스파게티로 보이지 않게 했다.
- **완전 투명(0)은 금지한다** — UX-SPEC 1장이 이미 "dim된 노드도 클릭
  가능해야 한다"고 정했으므로, 0으로 내리면 클릭 가능한 요소가 안 보이는
  상태가 되어 접근성·발견성 모두 깨진다. 0.16이 이 그래프에서 쓰는
  가장 낮은 불투명도이자 하한선이다.
- **레인 배경(`--graph-lane-bg`)과 연도축은 dim 대상에서 제외한다.** 이건
  "관계"가 아니라 "좌표계"이므로, 선택 중에도 그대로 100% 밝기를 유지해
  사용자가 지금 보고 있는 게 어느 분야·어느 연도대인지 놓치지 않게 한다.

### 시-4. 전환(transition)

- **지속시간 `--graph-sel-duration` 200ms, 이징 `--ease-standard`**
  (`cubic-bezier(.2,.7,.3,1)`, 기존 토큰 재사용). `DESIGN-SYSTEM.md` §8은
  "상시 인터랙션(카드 호버 등)에 120~180ms를 넘기지 말라"고 못박았지만,
  선택은 호버처럼 마우스가 지나갈 때마다 반복되는 게 아니라 **클릭이라는
  명시적 행동 1회**에 대응하는 전환이라 이 규칙의 "상시 인터랙션"에
  해당하지 않는다 — 그리고 노드/엣지 수십 개의 색·굵기·불투명도가 동시에
  바뀌는 큰 화면 변화라 180ms보다 약간 여유를 줘야 "깜빡임"이 아니라
  "전환"으로 읽힌다. 200ms는 §8 상한(180ms)보다 살짝 위지만 §4의
  `--duration-base`(180ms)~다음 단계 사이 값으로, 새 등급을 만들지 않고
  기존 스케일 감각 안에 머문다.
- **전환 대상은 `stroke`, `stroke-width`, `fill`, `opacity` 네 속성뿐이다.**
  위치(x/y)나 크기(rx, 노드 반지름)는 절대 트랜지션하지 않는다 — 노드가
  움직이거나 커지면 150개 노드 레이아웃에서 다른 노드와 겹치거나 밀려나는
  것처럼 보일 위험이 있다. 색·굵기·투명도만 바뀌므로 레이아웃은 항상
  고정이다.
- **선택 해제(다른 노드 클릭으로 즉시 전환되는 경우, 4장 표)도 같은 200ms를
  쓴다** — "해제는 애니메이션 없이 즉시"라는 4장 문구는 상호작용 흐름(카드가
  즉시 새 내용으로 바뀐다는 뜻)이지, 그래프 위 색 전환 자체를 끊어서
  깜빡이게 하라는 뜻으로 읽지 않는다. 이전 선택의 강조색이 즉시 사라지고
  새 선택의 강조색이 200ms에 걸쳐 나타나는 것이 아니라, 두 전환이 같은
  200ms 구간에서 동시에 크로스페이드되는 편이 매끄럽다 — FE 구현 시 "해제
  즉시 dim 원복 후 재계산"이 아니라 "다음 선택 상태로 클래스만 즉시
  갈아끼우고 CSS 트랜지션이 알아서 보간하게" 두는 방식을 권장한다(별도
  JS 애니메이션 루프 불필요).
- **`prefers-reduced-motion: reduce`에서는 `--graph-sel-duration:0ms`**
  (`css/tokens.css`에 이미 정의). 트랜지션이 꺼지면 상태가 즉시 전환되고,
  transform 기반 효과(글로우 확대 등)를 애초에 안 썼으므로 reduced-motion
  사용자도 정보 손실 없이 같은 최종 상태를 즉시 본다 — "덜 부드럽게"가
  아니라 "그냥 즉시" 전환이라, motion 민감 사용자에게 새로운 대체 UI를
  따로 설계할 필요가 없다.

### 시-5. 선택 정보 카드

**표면 규칙** (배경·테두리·그림자는 `DESIGN-SYSTEM.md` §5 컴포넌트 표의
"호버 카드/툴팁" 취급을 그대로 따른다 — 이 카드는 커맨드 팔레트 같은
전면 모달이 아니라 그래프 안에서 보조로 뜨는 패널이므로 `--shadow-3`이
아니라 한 단계 낮은 `--shadow-2`를 쓴다):

| 속성 | 토큰 | 값 |
|---|---|---|
| 배경 | `--graph-card-bg` | `--surface-raised` |
| 테두리 | `--graph-card-border` | 1px `--border-strong` |
| 그림자 | `--graph-card-shadow` | `--shadow-2` |
| 라운드 | `--graph-card-radius` | `--radius-md`(10px) — 카드 등급, `--radius-lg` 아님 |
| backdrop-blur | 없음 | `DESIGN-SYSTEM.md` §8: 이 효과는 커맨드 팔레트 1곳 전용, 여기 확장하지 않는다 |

**위치 규칙**:
- **노드를 따라다니지 않는다.** 그래프는 확대/축소·팬이 가능하므로(`.graph-viewport`
  transform), 카드를 노드 좌표에 절대 위치로 anchor하면 팬·줌마다 위치를
  재계산해야 하고 150개 노드가 몰린 화면에서는 카드가 다른 노드를 가릴
  위험이 크다. 대신 **`.graph-box` 컨테이너 하단에 고정된 슬라이드업
  패널**로 둔다 — 노드가 어디 있든 카드는 항상 같은 자리에 뜬다(위치를
  한 번만 학습하면 됨, UX-SPEC 8장이 요구하는 "두 그래프에서 동일한 규칙"과도
  맞는다).
- 패널 너비: 그래프 뷰포트 너비를 넘지 않는 고정폭(예: 380~420px, FE 재량),
  왼쪽 정렬. 그래프가 좁아지는 화면(로컬 그래프가 페이지 본문 폭에 종속될
  때)에서는 컨테이너 전체 폭으로 늘어나는 반응형 처리를 허용한다.
- z-index: SVG보다 위, 페이지의 다른 오버레이(커맨드 팔레트 등)보다는
  아래 — 동시에 뜰 일은 없지만 명시해 둔다.
- 카드가 열려 있는 동안 그래프 자체의 세로 스크롤 영역을 가리지 않도록
  `.graph-box`에 카드 높이만큼 하단 패딩을 확보한다(카드가 그래프 위에
  얹히는 오버레이가 아니라 컨테이너 안에서 공간을 차지하는 방식이면 이
  문제 자체가 없다 — 어느 쪽이든 FE 구현 재량이나, 마지막 노드 행이
  카드에 가려지지만 않으면 된다).

**내용 영역의 시각 규칙** (구조는 UX-SPEC 3장이 정함 — 여기서는 스타일만):
- 제목(논문명): `--fs-h4`, `--text-primary`.
- 연도·성장단계 배지: 배지는 §5.1의 기존 성장 단계 뱃지 컴포넌트를 그대로
  재사용한다(새 배지 스타일을 만들지 않는다) — 아이콘+라벨 전체 노출 버전
  ("논문 페이지 상단"과 같은 급, 카드는 이미 선택이라는 의도적 행동을 거친
  뒤라 축약할 이유가 없다).
- 부모/자식 개수 요약: 숫자 부분에 각각 `--graph-sel-parent`/`--graph-sel-child`
  텍스트 색을 써서, 그래프에서 방금 본 강조색과 카드 안의 숫자가 같은
  색으로 이어진다("부모 3 · 자식 5"에서 "3"은 모래색, "5"는 슬레이트색) —
  그래프와 카드 사이에 시각적 연속성을 준다. 단 이 색은 12px 이하 작은
  텍스트에도 §시-1 대비표 기준을 만족하므로 별도 조정 없이 그대로 쓴다.
- 이동 버튼("이 논문으로 이동 →"): 라이트에서는 `--accent-strong` 배경의
  채움 버튼, 다크에서는 §2.4 규칙(다크 accent를 넓은 면에 채우지 않음)에
  따라 **아웃라인 버튼**(테두리 `--accent`, 텍스트 `--accent`, 배경 투명)
  으로 낸다 — 이 사이트에서 채움 버튼이 라이트/다크에 따라 형태 자체가
  바뀌는 유일한 예외 컴포넌트지만, §8을 어기지 않으려면 여기서 갈라야
  한다. 버튼은 카드 안에서 유일한 강조색 사용처(§8 "페이지당 accent 3곳"
  제한과 별개로, 카드 자체가 이미 accent 선택 상태의 연장이므로 카드
  안에서는 예외로 친다).
- 닫기(×): `--text-tertiary`, hover 시 `--text-secondary`. 강조색을 쓰지
  않는다(닫기는 "이 카드에서 가장 안 중요한 행동"이라 시각적으로도
  가장 약해야 한다).

### 시-6. 두 그래프에서의 차이

전체/분야 계보도(연도 x축 + 레인)와 로컬 그래프(부모 위·자식 아래 행)는
방향의 **공간적 배치가 이미 다르다** — 전자는 좌(과거)→우(미래), 후자는
위(부모)→아래(자식). `--graph-sel-parent`/`-child` 색은 두 그래프 모두
동일하게 쓴다(그래프마다 색이 바뀌면 "이 색이 뭘 뜻하는지" 매번 다시
학습해야 한다). 공간 배치가 다른 건 이미 UX-SPEC이 정한 레이아웃이고,
색이 방향과 별개로 일관되면 사용자는 "왼쪽/위 = 모래색 = 과거,
오른쪽/아래 = 슬레이트색 = 미래"라는 연상 하나만 익히면 두 화면 모두에서
통한다.

로컬 그래프의 중심 노드(`node-center`)는 UX-SPEC 8장에 따라 선택 대상이
아니지만, 시각적으로는 **이미 선택된 것과 동일하게** 그린다 — 지금
`.localgraph svg .node-center rect{fill:color-mix(in srgb,var(--accent) 18%,var(--panel2));stroke:var(--accent)}`
(기존 `css/wiki.css` 구현, 건드리지 않음)가 정확히 `--graph-sel-node-fill`/
`--graph-sel-node-border`와 같은 색상 언어를 이미 쓰고 있다 — 새로 맞출
필요 없이 우연히 일치한다. 다만 굵기는 기존 구현값을 그대로 두고
`--graph-sel-node-border-w`(2.5px)로 통일할지는 FE 구현 시 기존 값을
확인해 맞추도록 남겨둔다(현재 소스에 명시적 굵기가 없어 브라우저 기본
1px로 보임 — 새 선택 노드 규칙과 통일하는 게 일관성에 맞다).
