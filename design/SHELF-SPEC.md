# 책장(bookshelf) 상호작용 스펙 — 홈의 446개 책등

작성자: 인터랙션 디자이너 · 대상: 프론트엔드 구현자
전제: `LIBRARY-BRIEF.md`(은유·금지사항), `UX-SPEC.md`(IA·화면구조), `GRAPH-INTERACTION.md`(계보 그래프 상호작용 — 이 문서와 원칙을 맞춘다). 시각 토큰(색·그림자·라운드·트랜지션)은 전부 `css/tokens.css`에 이미 있는 것만 참조한다. 새 토큰 이름을 이 문서에서 만들 필요가 있으면 §9에 모아 비주얼 디자이너에게 인계한다.

---

## 0. 그래프 규약과의 관계 — 다르게 정한다, 이유

`GRAPH-INTERACTION.md`의 핵심 원칙은 "클릭=선택(관계 강조), 이동은 카드 버튼으로"다. 그래프에서 이 분리가 필요한 이유는 명확하다 — 노드를 잘못 눌러 계보 탐색 중에 매번 페이지를 이탈하면 탐색 자체가 불가능해지기 때문이다.

책장에는 **그 이유가 없다.** 책등은 "이 책이 무엇과 연결됐는지 비교하는" 탐색 도구가 아니라 브리프 §5가 정의한 진입로("여기 뭐가 있나, 어디서 시작하나") 그 자체다. 책장 위에서 강조할 "관계"가 존재하지 않는다 — 책등에는 부모/자식 화살표가 없고, 서가 배치 자체가 이미 분야·트랙별로 뭉쳐 있어 이웃 관계는 공간적으로 다 보인다. 그래프처럼 "선택 → 무엇과 연결됐는지 확인 → 버튼으로 이동"이라는 2단계를 강제하면, 오히려 브리프가 요구하는 "서재에 들어섰다"는 즉각적 몰입감을 방해하는 군더더기 클릭이 된다.

**따라서 책장은 그래프와 다른 원칙을 쓴다: 책등 선택 = 미리보기(표지 카드), 표지 카드 위의 "펼쳐보기" 액션(또는 Enter 재입력) = 이동.** 완전히 즉시 이동(1클릭)으로 가지 않는 이유는 §2에서 다룬다 — 요약하면 446개 중 오클릭 비용(잘못 눌러 페이지 이탈)이 실제로 존재하고, 표지 미리보기 자체가 브리프 §5 질문 4("이 분야는 어디까지 채워졌나")에 답하는 콘텐츠(성장 단계, 저자 유무)를 담기 때문에 "선택 → 확인 → 이동"이 아니라 "선택 = 이미 유용한 정보 노출, +1클릭으로 이동"의 형태로 맞춘다. 즉 **그래프와 같은 원칙(클릭=선택, 이동은 별도)을 쓰되, 이동까지 필요한 중간 확인 정보의 성격이 다르므로 카드의 역할과 닫힘 조건을 책장에 맞게 재정의한다** — 아래 각 절에서 다른 점마다 근거를 명시한다.

## 1. 책등의 상태 기계

446개 책등은 각각 `<a>`(또는 `role="link"` 낸 `<div>`, §4 참조) 하나이며 `data-slug`, `data-field`를 갖는다. 상태는 서로 배타적이지 않다 — 예: "포커스 + 방문함"은 동시에 존재한다.

| 상태 | 트리거 | 시각 변화(정확한 값) | 근거 |
|---|---|---|---|
| 기본(default) | — | 책등 배경 = `var(--field-<f>)`(자기 분야색, 불투명 100%), 텍스트 = 분야색 위에서 WCAG 3:1 이상 확보되는 대비색(라이트: 흰색 또는 `--n-900` 중 자동 판정 — §9-1 참고), 테두리 없음 | 브리프 §1 "책등 색=분야색"을 문자 그대로 구현. 장식 테두리를 안 그리는 이유는 §2.4(스큐어모피즘 금지)—책등끼리 딱 붙어 서가처럼 보이려면 여백이 아니라 색 경계만으로 구분돼야 한다 |
| 호버(hover, 마우스만) | `:hover` | `translateY(-3px)` + `box-shadow: var(--shadow-1)`만(그림자는 §2.4 참조), 트랜지션 `120ms var(--ease-standard)`(기존 `--duration-fast`) | 그래프 노드 호버(`--graph-node-border-hover`, 테두리만 바뀌고 이동 없음)와 다르게 책등은 살짝 들리는 것을 허용한다 — 책 한 권을 "살짝 뽑아보는" 은유이자 책등이 촘촘히 붙어 있어 테두리 강조만으로는 안 보이기 때문. 3px·120ms는 카드 호버(`.card:hover{translateY(-2px)}`, 기존 CSS)와 같은 어휘를 쓰되 세로로 긴 책등에 맞춰 1px만 키웠다 |
| 포커스(focus, 키보드) | `:focus-visible` | 기존 전역 규칙 그대로: `outline:2px solid var(--accent); outline-offset:2px`. 호버 효과(translateY)는 포커스만으로는 주지 않는다 | 전역 규칙 재사용 원칙(§2.6 "새 토큰 임의 생성 금지"에 준함) — 포커스에 translateY까지 얹으면 로빙 tabindex로 방향키 이동할 때마다 446개 중 지나가는 책마다 레이아웃이 흔들려 어지럽다 |
| 선택됨(selected, 표지 카드 열림) | 클릭/Enter | `outline: 2px solid var(--accent)`(포커스와 같은 링, 포커스가 없어도 유지됨) + 책등 우측에 3px 폭 `var(--accent)` 세로 바(책이 살짝 빠져나온 인상, 3D 회전 없이 색 바로만 표현) | 그래프의 "선택 노드=accent 테두리+fill 14% tint"와 같은 색 언어를 쓴다(§0에서 "그래프와 다른 절차, 같은 색 어휘"로 통일). fill을 책등 전체에 덮지 않는 이유: 책등은 이미 분야색이 fill이라 위에 accent tint를 덮으면 분야색이 오염돼 "무슨 분야였는지" 순간적으로 안 읽힌다 |
| 방문함(visited) | `localStorage`에 slug 기록 있음 | 책등 우상단에 4×4px 점(`var(--text-tertiary)`, 저채도) — 색이 아니라 아주 작은 표식만 | 브리프 §5 질문3("내가 보던 게 뭐였나")과 연결되지만, 여기서 목적은 강조가 아니라 "이미 와봤다"는 미세한 재인(recognition) 신호다. 점 색을 강조색으로 쓰지 않는 이유: 446권 중 방문함이 누적되면(오래 쓴 위키일수록 수백 개) 강조색 점이 서가 전체에 흩뿌려져 분야색 리듬을 깬다 — §2.4의 "은유는 색·비례·리듬으로 표현" 원칙을 지키려면 방문 표식은 리듬을 침범하지 않을 만큼 작아야 한다 |
| 흐려짐(dimmed, 필터 제외) | 현재 필터 축(분야/트랙/연도/단계)에 안 걸림 | `opacity:0.28`, 책등 그룹 전체(텍스트 포함)에 적용. **클릭/포커스는 계속 가능**(완전 비활성화 아님) | `GRAPH-INTERACTION.md` 시-3의 "무관 노드 dim=0.32, 완전 투명 금지, 클릭 가능 유지" 원칙을 그대로 가져온다 — 같은 사이트에서 "흐려짐"이 어떤 화면에서는 클릭되고 어떤 화면에서는 안 되면 사용자가 매번 다시 학습해야 한다. 0.28은 0.32와 사실상 동일한 인상이되, 책등은 그래프 노드보다 면적이 커서(그래프 노드 폭 126px vs 책등은 20~40px 폭이지만 높이가 훨씬 큼) 같은 불투명도라도 지각되는 밝기가 달라 실측 후 근사치로 살짝 낮췄다(FE 구현 시 스크린샷 비교로 0.28~0.32 사이 재조정 허용) |
| 씨앗(stage=seed) | `graph.json` stage | 분야색 fill 대신 **해당 분야색의 아웃라인만**(배경은 `var(--bg-page)`, 테두리 1.5px 분야색, 점선 아님 — 점선은 이미 그래프에서 seed 표시로 쓰고 있어 겹치는 의미는 유지하되 책등은 촘촘히 붙어 점선이 시각적 노이즈가 되므로 실선 아웃라인으로 대체), 하단에 🌿🌳🌲 대신 브리프 §2가 금지한 "장식 이모지"를 책등엔 안 쓰고 대신 얇은 하단 바 색상만 단계별로 미세 변화(정확한 색은 비주얼 디자이너, `--stage-*` 재사용) | 브리프 §5 질문4 "빈 칸도 정직하게" — 씨앗 책이 꽉 찬 책처럼 보이면 정직하지 않다. 다만 완전히 비운 책등(테두리도 없음)은 서가에 구멍이 뚫린 것처럼 보여 446권 전체 규모감(질문1)을 해치므로, "얇지만 자리는 지키는 책"으로 표현 |

**상태 우선순위(동시 발생 시 렌더 순서)**: dim은 다른 모든 상태 위에 곱해진다(선택된 책이 필터로 dim 대상이 되는 일은 없다 — §5에서 필터 변경 시 선택 해제 규칙으로 방지). 포커스 링은 항상 최상위(다른 상태의 색 위에 덧그려짐).

## 2. 꺼내기(선택) 동작 — 표지 카드

**형태: 인라인 확장이 아니라 하단 고정 슬라이드업 패널.** `GRAPH-INTERACTION.md` 시-5와 동일한 패턴(그래프 정보 카드)을 재사용한다 — 이유는 두 가지다.
1. **일관성**: 이 사이트에서 "무언가를 선택하면 카드가 뜨는" 패턴이 이미 그래프에 있다. 책장에서 다른 패턴(예: 인라인으로 책이 커지며 표지가 나타나는 방식)을 쓰면 사용자가 화면마다 다른 UI 언어를 새로 학습해야 한다.
2. **성능**: 인라인 확장은 클릭한 책 주변 그리드가 리플로우된다 — 446개 grid item 중 하나의 크기가 바뀌면 브라우저가 전체 grid 트랙을 재계산해야 한다(§5에서 다룰 FLIP 배제와 같은 이유). 고정 패널은 그리드에 전혀 손대지 않는다.

**위치**: 뷰포트(또는 `.shelf` 컨테이너) 하단에 고정된 패널, 폭은 그래프 카드와 같은 규칙(고정폭 380~420px 데스크톱, 좁은 화면은 전체 폭). 노드를 따라다니지 않는 이유도 그래프와 동일 — 446권이 스크롤되는 중에도 카드 위치가 안정적이어야 팬닝하며 여러 책을 훑어볼 때 카드가 화면을 이리저리 옮겨 다니지 않는다.

**내용**: 표지 이미지(`/data/papers/<slug>/pages/p-01.png`, 없으면 분야색 배경에 제목만 — 브리프 §3 "일부 논문은 저자 정보 없을 수 있음, 레이아웃 안 깨져야" 원칙을 이미지 부재에도 동일 적용), 제목·저자·연도, 성장 단계 배지(그래프 카드와 같은 배지 컴포넌트 재사용), 그리고 **"펼쳐보기 →"** 버튼 — 누르면 `#/p/<slug>`로 이동.

**다른 책을 선택하면**: 카드 내용이 즉시 교체된다(닫혔다 다시 열리는 애니메이션 없이 — 그래프의 "해제는 애니메이션 없이 즉시, 다음 상태로 크로스페이드" 원칙과 동일). 이전 책의 selected 아웃라인은 사라지고 새 책에 옮겨간다. **동시에 두 책을 선택할 수 없다** — 그래프의 "선택은 단일 상태" 원칙 그대로(책장도 "지금 이 책이 뭔지 확인"이 목적이지 여러 책 비교가 목적이 아니다).

**닫는 방법**:

| 동작 | 결과 |
|---|---|
| 카드 안 닫기(×) | 선택 해제, 카드 닫힘, 포커스는 방금 선택했던 책등으로 돌아온다 |
| 책장 빈 공간 클릭 | 선택 해제, 카드 닫힘 |
| **Esc** | 선택 해제, 카드 닫힘, 포커스는 책등에 유지(포커스 이동 없음) — `GRAPH-INTERACTION.md` 4장과 동일 규칙 |
| 이미 선택된 책을 다시 클릭 | 토글 해제 |
| 카드의 "펼쳐보기" 버튼 | 이동(해제가 아니라 페이지 전환이므로 카드는 새 페이지에서 자연히 사라짐) |

**즉시 이동을 안 쓰는 이유(재확인)**: 책등 폭이 좁고(§6에서 계산) 촘촘히 배치되므로, 스크롤/훑어보기 중 오클릭 확률이 그래프 노드보다 오히려 높다(그래프 노드는 126×40px, 책등은 20~40px 폭에 불과). 그래프가 오클릭 방지를 위해 선택-이동을 분리한 것과 같은 근거가 책장에는 "폭이 더 좁다"는 이유로 더 강하게 적용된다.

## 3. 키보드 내비게이션 — 로빙 tabindex + 타입어헤드

446개를 전부 Tab 순회시키지 않는다. `Tab`은 "책장 전체"에 한 번만 멈추고, 책장 안에서는 로빙 tabindex(`roving tabindex`, ARIA 그리드/리스트박스 패턴)로 이동한다.

**구조**: `.shelf-row`(서가, 분야 또는 트랙 단위) 컨테이너가 여러 개, 각 서가 안에 책등들. `tabindex="0"`은 **현재 활성 책등 단 하나**만 갖고 나머지는 `tabindex="-1"`. 페이지 첫 진입 시 활성 책등 = 각 서가의 첫 번째 책(또는 이전에 선택했던 책이 있으면 그 책).

| 키 | 상황 | 결과 |
|---|---|---|
| `Tab` | 책장 바깥 → 책장 | 책장의 활성 책등(로빙 tabindex가 가리키는 1개)으로 포커스 진입 |
| `Tab` | 책장 안(책등에 포커스) | 책장을 벗어나 다음 페이지 요소로 포커스 이동(책등 순회 안 함) |
| `→` / `↓` | 서가 안 | 다음 책등으로 이동(마지막이면 다음 서가 첫 책으로 넘어감 — 서가 경계를 넘나든다) |
| `←` / `↑` | 서가 안 | 이전 책등으로 이동(첫 책이면 이전 서가 마지막 책으로) |
| `Home` | 어디서든 | 전체 책장의 첫 책등 |
| `End` | 어디서든 | 전체 책장의 마지막 책등 |
| `PageDown` / `PageUp` | 어디서든 | 다음/이전 서가의 첫 책등으로(서가 단위 점프, 21개 분야를 빠르게 건너뛰기용) |
| 문자 키(a-z, 타입어헤드) | 어디서든 | 현재 커서 다음부터 제목/통칭이 그 문자로 시작하는 책등으로 점프(연속 입력 시 누적 검색, 500ms 무입력 시 초기화 — 표준 리스트박스 타입어헤드 동작) |
| `Enter` / `Space` | 책등에 포커스 | 그 책을 선택(§2의 "클릭"과 동일 취급) — 이동하지 않는다 |
| `Enter` | 이미 선택된 책등에 다시 포커스+Enter | §2 표의 "펼쳐보기"까지 단축하지 않는다(토글 해제로 취급, 클릭과 동일) — 이동은 반드시 카드의 버튼을 거친다. 키보드 사용자를 위한 예외를 만들면 마우스/키보드 동작이 갈라져 §0에서 세운 "그래프와 같은 절차 원칙"이 깨진다 |
| `Esc` | 카드가 열려 있을 때 | §2와 동일, 카드 닫힘 |

**방향키가 서가를 넘나드는 이유**: 그래프 스펙(`GRAPH-INTERACTION.md` 6장)은 "격자가 아니라 방향키를 도입하지 않는다"고 결정했다. 책장은 다르다 — 서가는 실제로 줄 단위 격자(각 서가가 한 줄 또는 랩핑된 여러 줄)이고, 사용자가 "다음 책"이라는 개념을 명확히 예측할 수 있다(제목 순/연도 순으로 나열되므로 시각적으로 옆 책이 곧 다음 순서). 그래프 노드는 폴딩된 레인이라 "다음"이 예측 불가능했지만 책장은 그렇지 않으므로 방향키를 채택한다.

## 4. 스크린리더

**책장 전체**: `role="region"` `aria-label="논문 서가, 446권"`(정확한 총 권수는 `WIKI.INDEX.length`로 런타임 계산, 하드코딩 금지). 서가(분야) 단위는 `role="group"` `aria-label="<분야명> 서가, N권"`.

**책등 하나**: `role="option"`(또는 서가를 `listbox`로 모델링하면 표준 ARIA 패턴과 맞음 — `.shelf-row`를 `role="listbox"` `aria-label`, 책등을 `role="option"` `aria-selected`) `tabindex`(로빙, §3). `aria-label`은 "제목, 저자, 연도, 상태"를 한 문장으로 읽는다.

실제로 읽힐 문장 예시:
- 일반 책: `"Attention Is All You Need, Vaswani 외, 2017년, 상록수 단계"`
- 저자 정보 없는 책(브리프 §3의 결손 데이터 케이스): `"Some Paper Title, 2019년, 자라는 중 단계"` — "저자 미상"이라고 채워 넣지 않는다(없는 정보를 있는 것처럼 말하지 않는다)
- 씨앗 책: `"CycleGAN, 2017년, 씨앗 단계 · 아직 정리 노트 없음"` — UX-SPEC 5.3의 "빈 화면 금지" 철학을 스크린리더에도 적용, 방문할 가치가 있다는 것을 명시
- 방문함: 위 문장 끝에 `" · 이전에 봤음"` 추가

**446권이 리스트로 읽힐 때 지루하지 않게 하는 구조**: 서가(그룹) 진입 시점에 스크린리더가 자연히 "그룹, 컴퓨터 비전 서가, 62권" 같은 그룹 경계 안내를 먼저 읽으므로(표준 `listbox`/`group` 동작), 사용자는 "다음 서가로 건너뛸까 이 서가를 훑을까"를 매 그룹 시작점에서 판단할 수 있다 — 이게 §3의 `PageDown`(서가 단위 점프)이 스크린리더 사용자에게도 그대로 유효한 이유다(그래프처럼 순서만 있고 그룹 경계 안내가 없는 구조와 다른 점). 완성률 배지("42/62편 정리됨")는 서가 그룹 label에 포함하지 않는다 — 매 서가 진입마다 숫자를 읽게 하면 정작 책 제목을 듣기까지 지연이 길어진다; 완성률은 시각적으로 서가 헤더에만 두고 스크린리더 문장은 책 이동에 집중시킨다.

## 5. 필터·정렬 전환 — FLIP 안 쓴다

**결정: FLIP(First-Last-Invert-Play) 애니메이션을 쓰지 않는다.** 필터·정렬이 바뀌면 책등은 **즉시 재배치**되고(위치 애니메이션 없음), dim 처리(§1)만 트랜지션한다.

**근거(성능 계산)**: FLIP은 전환 전후 각 요소의 bounding rect를 측정(`getBoundingClientRect`)한 뒤 transform으로 되돌리고 재생한다. 446개 전 요소에 대해 매 전환마다 최소 446×2회의 강제 리플로우(layout thrashing) 유발 지점이 생긴다 — read(이전 위치) → DOM 변경 → read(새 위치) → write(transform) 사이클에서 read 단계마다 브라우저가 pending 레이아웃을 동기 계산해야 하므로, 저사양 기기에서 446개 규모면 한 번의 필터 전환에 수백 ms의 메인 스레드 점유가 발생할 수 있다(정확한 값은 기기 의존적이지만, 그래프 스펙이 150개 노드의 색 트랜지션에도 "레이아웃 트랜지션은 절대 하지 않는다"고 못박은 것과 같은 우려가 3배 규모인 책장에서 더 크다). 반면 위치는 그대로 두고 dim opacity만 CSS 트랜지션하면 브라우저는 컴포지터 스레드에서 처리 가능해(opacity는 GPU 합성 가능 속성) 리플로우가 없다.

**대안으로 채택하는 것**: 필터가 바뀌면
1. 필터에 안 걸리는 책은 `opacity` 트랜지션(§1 dim, `120ms`)만 걸고 DOM 순서·grid 배치는 그대로 유지한다(즉 "숨김"이 아니라 "흐림" — 자리를 차지한 채로 dim된다). 이렇게 하면 grid reflow 자체가 없다.
2. **정렬**(연도순 ↔ 계보순 ↔ 미작성 우선)이 바뀔 때만 DOM 순서를 실제로 바꿔야 하는데, 이때도 FLIP 없이 즉시 재배치한다 — 정렬 전환은 필터 토글보다 훨씬 드문 조작(사용자가 명시적으로 정렬 드롭다운을 여는 행동)이라 "애니메이션 없이 바뀐다"는 인상이 필터 토글만큼 급작스럽게 느껴지지 않는다. 정렬 전환에만 국한해 브리프 §2 "페이지 넘김 애니메이션, 튀어나오는 효과, 시차 스크롤 없음"의 정신을 지킨다면 오히려 위치 애니메이션 자체가 브리프가 경계하는 "장난감스러움"에 가깝다.

**`prefers-reduced-motion: reduce`**: dim opacity 트랜지션도 `0ms`로 낮춘다(`css/tokens.css`의 기존 reduced-motion 블록에 책장 전용 트랜지션 변수를 추가해 같은 미디어쿼리 아래 묶는다, §9-2). FLIP을 애초에 안 쓰므로 reduced-motion에서 대체 UI를 별도로 설계할 필요가 없다 — 그래프 스펙 시-4와 동일한 이유.

## 6. 터치 — 최소 타깃 크기 계산과 좁은 화면 대체

**계산**: WCAG 2.5.5(AA 권고 기준, 실무 표준 44×44px 또는 Apple/Material의 44~48px)를 기준으로 삼는다. 책등의 "두께"(폭)는 브리프 §1에 따라 논문 노트 분량(`bytes`)에 비례해야 하는데, 446권을 한 화면 폭(모바일 360~430px 기준, 패딩 제외 실사용 폭 약 320~390px)에 다 펼치면 1권당 평균 폭이 0.7~0.9px에 불과하다 — **가로 스크롤 서가로 만들어도** 손가락으로 개별 책 하나를 정확히 짚으려면 최소 44px가 필요한데, 시각적 "두께 비례" 은유를 지키는 한 44px를 보장할 방법이 없다(가장 얇은 책과 가장 두꺼운 책의 실제 바이트 차이가 수 배인데 전부 44px로 올리면 두께 차이 자체가 안 보여 은유가 무의미해진다).

**결론: 좁은 화면(뷰포트 폭 <768px 기준, 기존 반응형 브레이크포인트 확인 후 FE가 맞춤)에서는 책장을 책등 그리드로 렌더하지 않는다.** 대신 **분야별 카드 리스트**로 대체한다 — 이미 UX-SPEC 3.1의 분야 카드(색 바, 이름, 완성률)가 존재하므로 새 컴포넌트를 만들 필요 없이, 모바일 홈은 "분야 카드 → 탭하면 그 분야 논문을 세로 리스트(제목·연도·저자, 각 행 44px 이상 높이 확보 쉬움 — 세로 방향은 폭 제약이 없으므로)"로 드릴다운한다. 이는 브리프 §4 "좁은 화면에서는 은유를 줄이는 것이 정답"을 그대로 따르는 결정이다 — 책장 은유를 억지로 축소 렌더링해 타깃을 못 지키는 UI를 내놓느니, 모바일에서는 책장이라는 시각적 장치 자체를 내려놓고 실용적 리스트로 전환한다.

**중간 화면(태블릿, 768~1024px 등)**: 책등 폭이 평균 44px 이상 나오는지 실측 필요(446권 ÷ 화면에 실제 배치 가능한 줄 수 — 서가가 랩핑되어 여러 줄로 접힌다는 전제, `LIBRARY-BRIEF.md`는 책이 한 줄에 다 안 들어가면 여러 서가 줄로 접히는 것을 전제하므로) — FE가 실측 후 44px 미달 구간에서는 같은 대체(카드 리스트)를 적용할지 임계값을 조정한다. 이 문서는 원칙(44px 미달 시 책장 포기)만 확정하고 정확한 브레이크포인트 px 값은 실측을 요구한다.

## 7. 계보 그래프로의 연결 — 맥락 잃지 않기

경로: **책장(홈) → 책 선택(카드) → "펼쳐보기" → 논문 페이지 → 로컬 그래프/전체 계보도 → 다시 홈**.

1. **책장 → 논문 페이지**: §2의 카드를 거쳐 이동. 이동 시 그 책의 slug를 방문함(§1)으로 즉시 기록(`localStorage`) — 나중에 책장으로 돌아왔을 때 "아까 그 책"이 점으로 남아 있어야 맥락이 이어진다.
2. **논문 페이지 → 계보 그래프**: UX-SPEC 3.3절이 이미 정의한 섹션 9(로컬 그래프)로 자연 진입, 별도 신규 규칙 없음.
3. **계보 그래프 → 책장으로 복귀**: 브라우저 뒤로가기 또는 브레드크럼("전체지도")을 눌러 홈으로 돌아온다. **복귀 시 책장은 스크롤 위치와 마지막 선택 상태를 복원한다** — `sessionStorage`(탭 단위, 브라우저 세션 한정, `localStorage`의 영구 방문 기록과는 별개 저장소)에 "마지막으로 선택했던 slug"와 "책장 스크롤 offset"을 기록해 두고, 홈 라우트 진입 시 그 slug의 책등을 로빙 tabindex 활성 위치로 맞추고 화면도 그 지점으로 스크롤한다(카드는 자동으로 다시 열지 않는다 — 그래프 스펙 9장의 "선택은 URL에 반영 안 함, 페이지 이동 시 자연 소멸" 원칙과 같은 이유로, 돌아왔다고 카드가 저절로 뜨면 사용자가 요청하지 않은 UI가 나타나는 셈이다. 대신 "그 책이 어디 있었는지"만 강하게 알려준다: 포커스 위치 + 짧은 하이라이트 펄스, §9-3).
4. **하이라이트 펄스**: 복귀 시 해당 책등에 1회성 시각 신호(예: outline이 0→2px로 200ms 안에 나타났다 유지, 추가 반짝임 애니메이션 없음 — 브리프 §2 모션 금지 원칙, "복귀했다"는 정보 전달이 목적이지 주의를 끄는 효과가 목적이 아니다)를 주고 `prefers-reduced-motion`에서는 즉시 outline만 표시(트랜지션 생략).

이 경로 설계의 핵심은 "책장은 입구, 그래프는 관계 파악, 다시 책장은 이어보기"라는 순환에서 **매 단계 사용자가 지금 어디 있었는지 하나씩 흘리지 않는 것** — 방문 표식(1), 계보 페이지의 정상 진입(2), 스크롤+포커스 복원(3)이 그 세 지점에 각각 대응한다.

## 9. 비주얼 디자이너에게 인계 — 확정 필요 항목

1. **책등 텍스트 대비 자동 판정**: 21개 분야색 각각 위에서 텍스트가 흰색/검정 중 어느 쪽이 3:1 이상을 만족하는지 표로 확정(라이트/다크 각각). 밝은 분야색(예: `nlp` L `#956f18`)과 어두운 분야색(`foundations` L `#5c616d`)이 섞여 있어 텍스트 색을 고정할 수 없다.
2. **책장 전용 트랜지션 토큰**: `--shelf-hover-lift`(3px), `--shelf-hover-duration`(120ms), `--shelf-dim-opacity`(0.28), `--shelf-dim-duration`(120ms)를 `tokens.css`에 추가하고 기존 `:root` reduced-motion 블록(라인 464 부근)에 `--shelf-dim-duration:0ms` 등을 같이 묶을 것.
3. **하이라이트 펄스(§7-4)의 정확한 keyframe**: outline 등장 트랜지션의 easing·duration 확정(제안값은 200ms `--ease-standard`, 확정은 비주얼 디자이너 재량).
4. **씨앗 책등 하단 바 색상**(§1 씨앗 행): `--stage-*` 토큰을 그대로 쓸지, 분야색과 섞은 tint를 쓸지 결정.
